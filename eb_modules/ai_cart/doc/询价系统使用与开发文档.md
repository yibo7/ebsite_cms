## 二、系统使用

### 2.1 后台配置

#### AI 提供者配置（系统级）

AI 提供者已迁移至系统级插件管理，配置分两步：

**① 系统设置 → 选择默认 AI 提供者**

路径：网站后台 → 系统设置 → AI 提供者

| 字段 | 说明 |
|------|------|
| AI 提供者 | 下拉选择已安装的 AI 插件（DeepSeek / 阿里千问 / OpenAI / 京东JoyAgent） |

**② 插件管理 → 配置 API 密钥**

路径：网站后台 → 插件管理 → AI 提供者 → 点击对应插件

| 字段 | 说明 |
|------|------|
| API Key | 对应供应商的 API 密钥 |
| 模型名称 | 如 `deepseek-chat`、`qwen-plus`、`gpt-4o-mini` |

> 切换 AI 提供者后立即生效，无需重启。

#### 品类选择

| 选项 | 说明 |
|------|------|
| 打印复印耗材 | 按品牌+型号精确搜索（适用于鼓芯、粉盒） |
| 服装 | 按品类+颜色+尺码关键词模糊搜索（示例） |

> 切换品类后**需要重启项目**才能生效。

### 2.2 提示词配置

> 路径：报价单管理 → 提示词配置

允许管理员在不修改代码、不重启的情况下编辑 AI 的提示词：

| 配置项 | 用途 |
|--------|------|
| 店铺名称 | AI 文案中自称的名称 |
| 欢迎语 | 客户打开对话框时显示的欢迎消息（支持 HTML） |
| 提取提示词 | 指导 AI 从用户消息中提取产品参数 |
| 销售文案模板 | AI 撰写回复时使用的模板 |
| 引导提示词 | AI 无法提取参数时引导用户提供更多信息 |

> 修改提示词后**无需重启**，刷新页面即可生效。

### 2.3 前端使用

**前台地址：** `http://your-site/ai_cart`

**基本流程：**
1. 用户在左侧对话框输入需求（如 "Ricoh MPC8003 鼓芯多少钱"）
2. AI 提取参数 → 搜索数据库 → 返回匹配产品
3. 用户点击产品卡片上的 `[+]` 加入询价篮
4. 在询价篮中修改数量，点击"生成报价单"
5. 生成可分享的报价单链接

**支持的搜索方式：**
- 品牌 + 型号：`"Ricoh MPC8003"`
- 仅品牌：`"佳能鼓芯有哪些"`
- 仅型号：`"MPC8003"`
- OEM/SKU/料号：`"GX-C200-037"`
- 完整描述：`"Drum Unit for Ricoh MP 9000"`

**产品卡片功能：**
- 缩略图 → 点击在新窗口打开商品详情页
- 商品名称 → 点击在新窗口打开商品详情页
- 价格显示 → 根据数据库中的 `unit_price` 显示折后价，有原价时显示删除线对比

### 3.2 AI 聊天

```
POST /chat
{
    "messages": [
        {"role": "user", "content": "Ricoh MPC8003 报价"}
    ]
}
→ {
    "reply": "<p>...</p>",
    "matches": [
        {
            "title": "Ricoh MPC8003 鼓芯",
            "small_pic": "/uploads/xxx.jpg",
            "unit_price": 25.0,
            "market_price": 30.0,

        }
    ]
}
```

> `unit_price` 和 `market_price` 来自数据库实际值。
> `remarks` 不再返回给前端，仅在提交报价单时存入数据库。

### 3.3 生成报价单

```

            "market_price": 30.0,
            "class_name": "打印耗材",

            "remarks": "...",
            "qty": 5
        }
    ],
    "discount_rate": 0.10
}
→ {
    "code": 0,
    "record_id": "QRxxxxxx",
    "url": "/ai_cart/quote/QRxxxxxx"
}
```

## 四、数据模型

### 4.1 标准化商品数据结构

所有环节（API 返回 / 报价单存储 / 前端渲染）统一使用以下字段：

```python
{
    "title": "Ricoh MPC8003 鼓芯",      # 商品名称
    "small_pic": "/uploads/xxx.jpg",     # 商品封面图
    "unit_price": 25.0,                  # 单价（从 column_11 读取）
    "market_price": 30.0,                # 市场价（从 SKU JSON 提取）
    "class_name": "打印耗材",            # 分类名称
    "sku": "ObjectId字符串",             # SKU / 产品编号
    "url": "/a148.html",                 # 商品详情页链接
    "qty": 1,                            # 默认数量
}
```

> `remarks` 字段仅存储在报价单数据库中，AI 聊天接口不返回此字段。

### 4.2 CMS 商品表（NewsContent）

通过 `class_id` 过滤商品分类，各字段含义：

| 字段 | 用途 |
|------|------|
| `id` | 自增整数 ID，用于生成 `/a{id}.html` 详情 URL |
| `title` | 商品标题 |
| `small_pic` | 商品封面图 |
| `column_3` | 品牌（如 Ricoh、佳能） |
| `column_4` | 型号字段 1 |
| `column_5` | 型号字段 2 |
| `column_6` | OEM 码 / 货号 |
| `column_7` | 备注 / 规格说明 |
| `column_10` | SKU JSON 数组（`[{"sku":"...","marketPrice":...}]`） |
| `column_11` | 价格（数值） |

### 4.3 报价单表（ShopQuoteRecord）

| 字段 | 说明 |
|------|------|
| `record_id` | 唯一编号（如 QR65ab...） |
| `session_id` | 浏览器会话标识 |
| `user_id` | 登录用户 ID |
| `items` | 商品数组（存储标准化字段 + qty + subtotal） |
| `status` | `pending_review` → `approved` → `paid` → `completed` / `failed` |
| `total_original` | 原价合计 |
| `total_discount` | 折扣金额 |
| `total_final` | 最终报价 |
| `contact` | 客户联系方式 |

### 4.4 提示词配置表（ShopQuotePrompts）

单例文档 (`profile_key="default"`)：

| 字段 | 说明 |
|------|------|
| `shop_name` | 店铺名称 |
| `welcome_message` | 欢迎语 |
| `extract_prompt` | AI 提取参数提示词 |
| `sales_prompt_tpl` | 销售文案模板 |
| `guide_prompt` | 引导提示词 |

## 五、扩展开发

### 5.1 新增品类处理器

在 `ai_handlers/` 下创建新的 Handler 文件，例如 `furniture.py`：

```python
from . import AiHandlerBase, register_ai_handler

@register_ai_handler('furniture')  # 注册名，在后台品类下拉中显示
class FurnitureHandler(AiHandlerBase):
    display_name = "家具"  # 前端显示名称

    # 默认提示词（首次安装时写入 DB）
    default_shop_name = "优选家居"
    default_welcome_message = "欢迎选购家具..."
    default_extract_prompt = """你是一个家具销售助手...
提取字段：
- category: 家具品类（床、沙发、桌子 等）
- style: 风格（现代、中式、北欧 等）
- material: 材质（实木、布艺、皮质 等）
..."""
    default_sales_prompt_tpl = "..."
    default_guide_prompt = "..."

    def search(self, params: dict) -> list[dict]:
        """
        根据 AI 提取的参数搜索商品
        @param params: AI 提取的字段 dict
        @return: 标准化商品列表
        """
        products = []
        for product in matched_products:
            products.append({
                "title": ...,
                "small_pic": ...,
                "unit_price": ...,
                "market_price": ...,
                "class_name": "家具",
                "sku": ...,
                "url": ...,
            })
        return products

    def build_custom_instruction(self, params: dict, exact: bool) -> str:
        """构建 AI 文案的自定义指令"""
        if exact:
            return "客户明确说了家具品类。热情介绍产品...。"
        return "信息不完整。请客户看看这些是否匹配..."
```

注册后，后台模块配置的品类下拉框**会自动出现**新增的选项。

### 5.2 新增 AI 提供者

AI 提供者现在是系统级插件，在 `plugins/ai_providers/` 下创建，继承插件系统的 `AIProviderBase`：
可在后台的插件管理中配置。 

### 5.3 搜索逻辑说明

`printer_drum` Handler 的搜索策略：

```
输入参数:
  brand → column_3  (AND 条件)
  model → column_4 / column_5 / title  (AND $or)
  oem   → column_6 / column_7 / column_10 / title  (AND $or)

所有条件组合为 $and，多个条件同时缩小范围。
```

Python 兜底：当 MongoDB `$regex` 因列存储为数组而不生效时，全量查询后在各文本字段中做包含匹配。

## 六、常见问题

### Q: 切换品类后之前的提示词会被覆盖吗？
不会。`ensure_seeded()` 仅在数据库首次无配置时写入，切换品类后不会覆盖已有配置。如需重置可手动删除 `ShopQuotePrompts` 集合中的文档。

### Q: 为什么修改提示词后没有生效？
提示词配置无需重启。请刷新页面后重新发送消息。如果仍不生效，检查 `_get_prompt()` 的日志确认是否从 DB 读取到了值。

### Q: 商品搜不到怎么办？
1. 检查商品是否属于正确的 `class_id`（打印耗材：`6852498a0a8b42f2df14146e`）
2. 检查搜索关键词是否在 `column_3`~`column_10` 或 `title` 中
3. 查看后端日志中的 `[DEBUG 兜底搜索]` 确认是否进入兜底逻辑

### Q: 产品 URL 链接为什么打不开？
确保 `NewsContentModel.id` 在数据库中有正确的自增整数值。URL 生成方式为 `url_links.get_content_url(p.id)` → `/a{id}.html`。

### Q: AI 返回 401 错误或原始 JSON 字符串怎么办？
401 错误：检查插件管理中的 API Key 是否有效，或切换到其他 AI 提供者。
原始 JSON 字符串：确认使用的是新插件系统的 AI 提供者（`plugins/ai_providers/`），而非旧的模块内 `ai_providers/`。
