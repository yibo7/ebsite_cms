# 阶梯价模板功能 · 完整开发实施文档

## 一、功能背景

商城后台需要支持按分类批量配置阶梯价。商品数量少时逐个配置可行，但商品数量多、同分类商品定价规则一致时，逐个录入效率低。因此增加“阶梯价模板”功能，让运营可以：

- 创建模板，定义阶梯规则
- 预览模板应用到示例商品的效果
- 把模板应用到某个分类，批量生成该分类下所有商品的阶梯价
- 复制已有模板，快速创建相似模板
- 查看应用日志，追溯每次批量操作的结果

模板只改变运营的录入方式，不改变数据模型。应用后商品数据里存的仍然是固定单价，价格计算逻辑、前端展示、结算流程完全不受影响。


## 二、核心设计原则

**模板存“计算规则”，不存固定价格。** 因为同一分类下不同商品的零售价、成本价不同，如果模板存固定单价，所有商品阶梯价会一刀切，不合理。

**支持两种计价基准，由运营创建模板时选择：**

- **基于零售价折扣率**：`阶梯单价 = 商品零售价 × 折扣率`
- **基于成本价加价率**：`阶梯单价 = 商品成本价 × 加价率`

应用模板时，系统按每个商品自己的价格基准实时计算，生成差异化的固定单价写入商品数据。

**两种计价基准并存，不是二选一。** 每个模板独立选择自己的计价基准，不同模板可以用不同基准。同一个分类也可以先后应用不同模板。

## 四、数据模型

### 1. 模板集合 `PriceTemplate`

| 字段 | 说明 |
|---|---|
| `name` | 模板名称 |
| `category_id` | 适用分类 ID |
| `pricing_base` | 计价基准：`market_price` 或 `cost_price` |
| `tiers` | 阶梯规则数组，每项含 `min_qty`、`max_qty`、`rate` |
| `created_at` | 创建时间 |
| `updated_at` | 更新时间 |
| `created_by` | 创建人 ID |

### 2. 应用日志集合 `PriceTemplateLog`

| 字段 | 说明 |
|---|---|
| `template_id` | 模板 ID |
| `template_name` | 模板名称（冗余，模板删除后仍可读） |
| `category_id` | 适用分类 ID |
| `category_name` | 分类名称（冗余，避免每次关联查询） |
| `apply_mode` | `fill_empty` 或 `force_overwrite` |
| `total_products` | 遍历商品总数 |
| `success_count` | 成功应用数 |
| `skip_existing_count` | 跳过（已有规则）数 |
| `skip_missing_price_count` | 跳过（缺少价格基准）数 |
| `error_count` | 异常数 |
| `error_details` | 异常明细数组，每项含 `product_id`、`sku`、`reason` |
| `created_at` | 操作时间 |
| `created_by` | 操作人 ID |
| `created_by_name` | 操作人姓名（冗余，避免每次关联管理员表） |

## 六、文件结构与职责

### 1. `datas/price_template.py`

职责：

- 模板数据的增删改查
- 模板校验逻辑
- 表单档位解析
- 应用模板到分类的核心逻辑
- 统计分类下商品数
- 复制模板
- 获取示例商品（用于预览）

对外暴露的函数：

- `validate_template(data)` → 返回错误列表
- `parse_tiers_from_form(form)` → 解析表单中的档位数据
- `get_template_list()` → 获取模板列表（附带分类名称）
- `get_template(template_id)` → 获取单个模板
- `create_template(data, admin_user_id)` → 创建模板
- `update_template(template_id, data)` → 更新模板
- `delete_template(template_id)` → 删除模板
- `copy_template(template_id, admin_user_id)` → 复制模板，返回新模板 ID
- `apply_template_to_category(template_id, apply_mode, admin_user_id, admin_user_name)` → 应用到分类
- `count_products_in_category(category_id)` → 统计分类下商品数
- `get_sample_product(category_id)` → 获取该分类下的示例商品（用于预览）

**`get_sample_product` 的返回字段：**

- `product_id`：商品 ID
- `product_name`：商品名称
- `sku`：示例 SKU
- `marketPrice`：零售价
- `costPrice`：成本价

**`get_sample_product` 的选择规则：**

- 按创建时间倒序，取该分类下最新的一个商品
- 该商品必须有完整的 `marketPrice` 和 `costPrice`
- 如果最新商品价格数据不完整，继续往后找，直到找到一个价格数据完整的商品
- 如果该分类下没有任何价格数据完整的商品，返回 `None`

### 2. `datas/price_template_log.py`

职责：

- 应用日志的写入与查询

对外暴露的函数：

- `write_log(data)` → 写入一条日志
- `get_log_list(limit)` → 获取日志列表
- `get_log(log_id)` → 获取单条日志

### 3. `datas/__init__.py`

职责：

- 统一导出 `db`，供 `price_template.py` 和 `price_template_log.py` 导入
- 根据项目实际情况，从 `eb_common.db` 或其他模块导入

### 4. `shop_pages.py`

职责：

- 定义路由
- 调用 `datas` 层函数
- 处理表单提交与页面渲染
- 使用 `@check_admin_login` 装饰器

**新增路由函数：**

- `price_template_list()` → 渲染列表页
- `price_template_form(template_id=None)` → 渲染新建/编辑页（含预览数据），处理表单提交
- `price_template_delete(template_id)` → 删除模板
- `price_template_copy(template_id)` → 复制模板，复制后跳转到编辑页

## 九、预览功能说明

**作用：** 运营在模板表单页填写阶梯规则时，系统实时展示一个示例商品应用后的阶梯价，让运营在保存前看到效果。

**数据来源：**

- 页面加载时，Flask 渲染该分类下的示例商品，把 `marketPrice` 和 `costPrice` 写入页面。
- 示例商品的选择规则：
  - 按创建时间倒序，取该分类下最新的一个商品
  - 该商品必须有完整的 `marketPrice` 和 `costPrice`
  - 如果最新商品价格数据不完整，继续往后找，直到找到价格数据完整的商品
  - 如果该分类下没有任何价格数据完整的商品，预览区提示“该分类下暂无商品，无法预览”

**计价基准与预览商品的对应关系：**

- 如果运营选择“基于零售价折扣率”，预览区使用示例商品的 `marketPrice` 计算。
- 如果运营选择“基于成本价加价率”，预览区使用示例商品的 `costPrice` 计算。
- 切换计价基准时，预览区自动切换计算基准。

**分类切换的处理：**

- 运营在表单中切换适用分类时，预览区的示例商品需要同步更新。
- 由于表单是同步提交模式，切换分类后需要一次页面刷新才能加载新分类的示例商品。
- 实现方式：分类下拉框变更时，触发表单提交（或页面跳转），重新加载页面并带入新分类，预览区随之更新。
- 如果不希望每次切换分类都刷新页面，可以退一步：预览区在页面加载时确定示例商品，运营切换分类后需要保存再查看。此方案的取舍需要在实现时确认。

**计算方式：**

- 运营修改计价基准或系数时，脚本读取基准值，按当前系数计算每一档单价，更新预览区。
- 基于零售价时：`预览单价 = 示例商品零售价 × 折扣率`
- 基于成本价时：`预览单价 = 示例商品成本价 × 加价率`

**关键点：**

- 预览不写入任何数据，只做展示。
- 保存模板时，预览结果不作为数据来源，实际应用时按每个商品自己的价格基准重新计算。


## 十、应用模板的执行流程

1. 运营在模板列表点击“应用”
2. 进入应用确认页，展示模板信息和预计影响商品数
3. 选择应用方式（仅补充空白 / 强制覆盖）
4. 确认后提交表单
5. 系统遍历该分类下所有商品，对每个 SKU 执行：
   - 检查是否已有阶梯规则，已有且为“仅补充空白”则跳过
   - 检查价格基准是否存在，缺失则跳过
   - 按模板系数逐档计算单价
   - 保本校验，低于成本价则记录异常并跳过
   - 写入该 SKU 的阶梯价数据
6. 遍历完成后写入应用日志
7. 页面提示结果并跳转到日志页

**预计影响商品数的计算口径：**

- 统计该分类下所有商品数，不区分是否已有阶梯规则
- 这个数字只是参考，实际应用时会根据应用方式跳过部分商品

**执行方式：**

- 初期商品少时同步执行，页面等待结果后跳转。
- 如果后续单个分类下商品数超过 500，建议改为后台任务，页面提示“正在应用，请稍后查看日志”。
- 具体采用哪种方式，根据项目实际情况决定，文档不做硬性要求。


## 十一、复制模板说明

**复制流程：**

1. 运营在模板列表点击“复制”
2. 系统复制该模板的计价基准、阶梯规则
3. 新模板名称自动加后缀，如“塑料制品批发价 - 副本”
4. 复制后跳转到编辑页，让运营修改名称和系数
5. 复制后不自动应用，需要运营手动点击“应用”

**关键点：**

- 复制只复制模板本身，不影响商品数据。
- 复制后模板的 `created_at` 为新时间，`created_by` 为当前操作人。


## 十二、删除模板说明

**删除流程：**

1. 运营在模板列表点击“删除”
2. 弹出确认弹窗，提示“删除后不影响已应用的阶梯价数据”
3. 确认后删除模板

**关键点：**

- 删除只删除模板本身，不影响商品数据。
- 应用日志中保留 `template_name` 冗余字段，即使模板被删，日志仍可读。
- 删除前弹出确认，避免误操作。


## 十三、校验规则

**模板保存时校验：**

- 模板名称不能为空
- 必须选择适用分类
- 计价基准必须合法
- 至少有一个档位
- 区间连续、不重叠
- 最后一档上限必须为空
- 系数随数量递增而递减
- 基于成本价加价率时，所有系数 ≥ 1
- 基于零售价折扣率时，所有系数 ≤ 1

**应用时校验：**

- 计算出的单价低于成本价 → 跳过该商品，记录异常


## 十四、关键设计点

**第一，模板不能存固定单价。** 必须存系数（折扣率或加价率），应用时按每个商品自己的价格基准计算，否则同分类商品阶梯价会一刀切。

**第二，两种计价基准并存。** 运营创建模板时选择一种，不同模板可以用不同基准。这样既能适配零售价稳定的品类，也能适配成本波动大的品类。

**第三，预览是保存前的必要辅助。** 运营在保存前看到示例商品的计算结果，能立刻发现系数填错，减少来回修改。

**第四，应用前必须让运营确认。** 应用会批量修改商品数据，属于高风险操作，必须经过确认页。

**第五，应用日志必须记录。** 谁在什么时候把哪个模板应用到了哪个分类，影响多少商品，异常多少条，都要可追溯。日志中冗余存 `template_name`、`category_name`、`created_by_name`，避免模板删除后日志不可读。

**第六，强制覆盖要二次确认。** 强制覆盖会重写所有商品的阶梯价，运营点击后应该弹出二次确认，避免误操作。

**第七，复制模板方便快速创建相似模板。** 运营可以复制一个已有模板，修改名称和部分系数，快速创建新模板。复制后不自动应用，需手动确认。

**第八，删除模板不影响已有数据。** 删除只删除模板本身，已应用的阶梯价数据和历史日志不受影响。

**第九，数据模型不变。** 模板只是计算工具，应用后商品数据里存的仍然是固定单价。价格计算逻辑、前端展示、结算流程完全不受影响。

**第十，标签导航统一。** 所有商城后台页面顶部都添加标签导航，方便在订单管理、价格级别管理、阶梯价模板等模块间切换。当前页面高亮 `active`。


## 十五、一句话总结

**新增“阶梯价模板”功能，运营按分类创建模板，选择计价基准（零售价折扣率 或 成本价加价率），填写阶梯系数，保存前可预览示例商品的计算结果。应用时按每个商品自己的价格基准计算每一档的固定单价，保本校验后写入商品数据。支持复制模板、查看应用日志、追溯异常明细。两种计价基准并存，不同模板可用不同基准。页面继承公共框架，使用 Bootstrap 5.3 类，顶部加标签导航。模板只是计算工具，不改变数据模型，不影响价格计算逻辑。**
