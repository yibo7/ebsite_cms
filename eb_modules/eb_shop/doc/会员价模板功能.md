# 会员价模板功能 · 完整开发实施文档

## 一、功能背景

商城后台需要支持按分类批量配置会员价。商品数量少时逐个配置可行，但商品数量多、同分类商品定价规则一致时，逐个录入效率低。因此增加“会员价模板”功能，让运营可以：

- 创建模板，定义每个会员组的系数
- 把模板应用到某个分类，批量生成该分类下所有商品的会员价
- 查看应用日志，追溯每次批量操作的结果

模板只改变运营的录入方式，不改变数据模型。应用后商品数据里存的仍然是固定价格，价格计算逻辑、前端展示、结算流程完全不受影响。


## 二、核心设计原则

**模板存“计算规则”，不存固定价格。** 因为同一分类下不同商品的零售价、成本价不同，如果模板存固定价格，所有商品会员价会一刀切，不合理。

**支持两种计价基准，由运营创建模板时选择：**

- **基于零售价折扣率**：`会员价 = 商品零售价 × 折扣率`
- **基于成本价加价率**：`会员价 = 商品成本价 × 加价率`

应用模板时，系统按每个商品自己的价格基准实时计算，生成差异化的固定价格写入商品数据。

**会员组是系统已有的固定集合，不是运营自定义的。** 模板表单直接把系统里所有会员组列出来，运营给每个组填系数即可。

## 四、数据模型

### 1. 模板集合 `MemberPriceTemplate`

| 字段 | 说明 |
|---|---|
| `name` | 模板名称 |
| `category_id` | 适用分类 ID |
| `pricing_base` | 计价基准：`market_price` 或 `cost_price` |
| `group_rates` | 会员组系数数组，每项含 `group_id`、`group_name`、`rate` |
| `created_at` | 创建时间 |
| `updated_at` | 更新时间 |
| `created_by` | 创建人 ID |

**`group_rates` 示例：**

```json
[
    {"group_id": "66b4926df455dd91ca3de33e", "group_name": "svip", "rate": 0.75},
    {"group_id": "66b4924ff455dd91ca3de33d", "group_name": "vip",  "rate": 0.85}
]
```

### 2. 应用日志集合 `MemberPriceTemplateLog`

| 字段 | 说明 |
|---|---|
| `template_id` | 模板 ID |
| `template_name` | 模板名称（冗余，模板删除后仍可读） |
| `category_id` | 适用分类 ID |
| `category_name` | 分类名称（冗余，避免每次关联查询） |
| `apply_mode` | `fill_empty` 或 `force_overwrite` |
| `below_cost_strategy` | 低于成本价的处理策略：`skip` / `floor_to_cost` / `reject_all` |
| `total_products` | 遍历商品总数 |
| `group_count` | 本次应用涉及的会员组数 |
| `success_count` | 成功应用数 |
| `skip_existing_count` | 跳过（已有会员价）数 |
| `skip_missing_price_count` | 跳过（缺少价格基准）数 |
| `error_count` | 异常数 |
| `floor_count` | 按成本价兜底的商品数（仅策略二时有值） |
| `error_details` | 异常明细数组，每项含 `product_id`、`sku`、`group_name`、`reason` |
| `created_at` | 操作时间 |
| `created_by` | 操作人 ID |
| `created_by_name` | 操作人姓名（冗余） |
| `snapshot` | 预留字段，暂不填，后续做回滚时使用 |

## 六、文件结构与职责

### 1. `datas/member_price_template.py`

职责：

- 模板数据的增删改查
- 模板校验逻辑
- 表单会员组系数解析
- 应用模板到分类的核心逻辑
- 统计分类下商品数
- 复制模板
- 获取示例商品（用于预览）
- 获取系统所有会员组（用于表单展示）

对外暴露的函数：

- `validate_template(data)` → 返回错误列表
- `parse_group_rates_from_form(form)` → 解析表单中的会员组系数
- `get_template_list()` → 获取模板列表（附带分类名称）
- `get_template(template_id)` → 获取单个模板
- `create_template(data, admin_user_id)` → 创建模板
- `update_template(template_id, data)` → 更新模板
- `delete_template(template_id)` → 删除模板
- `copy_template(template_id, admin_user_id)` → 复制模板，返回新模板 ID
- `apply_template_to_category(template_id, apply_mode, below_cost_strategy, admin_user_id, admin_user_name)` → 应用到分类
- `count_products_in_category(category_id)` → 统计分类下商品数
- `get_sample_product(category_id)` → 获取该分类下的示例商品（用于预览）
- `get_all_member_groups()` → 获取系统所有会员组（用于表单展示）

**`get_sample_product` 的返回字段：**

- `product_id`：商品 ID
- `product_name`：商品名称
- `sku`：示例 SKU
- `marketPrice`：零售价
- `costPrice`：成本价

**`get_sample_product` 的选择规则：**

- 按创建时间倒序，取该分类下最新的一个商品
- 该商品必须有完整的 `marketPrice` 和 `costPrice`
- 如果最新商品价格数据不完整，继续往后找，直到找到一个价格数据完整的商品
- 如果该分类下没有任何价格数据完整的商品，返回 `None`

**`get_all_member_groups` 的返回字段：**

- `group_id`：会员组 ID
- `group_name`：会员组名称

### 2. `datas/member_price_template_log.py`

职责：

- 应用日志的写入与查询

对外暴露的函数：

- `write_log(data)` → 写入一条日志
- `get_log_list(limit)` → 获取日志列表
- `get_log(log_id)` → 获取单条日志

### 3. `shop_pages.py`

职责：

- 定义路由
- 调用 `datas` 层函数
- 处理表单提交与页面渲染
- 使用 `@check_admin_login` 装饰器

**新增路由函数：**

- `member_price_template_list()` → 渲染列表页

## 九、预览功能说明

**作用：** 运营在模板表单页填写会员组系数时，系统实时展示一个示例商品应用后的会员价，让运营在保存前看到效果。

**数据来源：**

- 页面加载时，Flask 渲染该分类下的示例商品，把 `marketPrice` 和 `costPrice` 写入页面。
- 示例商品的选择规则：
  - 按创建时间倒序，取该分类下最新的一个商品
  - 该商品必须有完整的 `marketPrice` 和 `costPrice`
  - 如果最新商品价格数据不完整，继续往后找，直到找到一个价格数据完整的商品
  - 如果该分类下没有任何价格数据完整的商品，预览区提示“该分类下暂无商品，无法预览”

**计算方式：**

- 运营修改计价基准或系数时，脚本读取基准值，按当前系数计算每个会员组的预览价格。
- 基于零售价时：`预览价格 = 示例商品零售价 × 折扣率`
- 基于成本价时：`预览价格 = 示例商品成本价 × 加价率`
- 切换计价基准时，预览区自动切换计算基准。
- 系数留空的会员组，预览列也留空。

**展示位置：** 预览价格直接展示在会员组系数表格的“预览”列中。

**关键点：** 预览不写入任何数据，只做展示。保存模板时，预览结果不作为数据来源。


## 十、应用模板的执行流程

1. 运营在模板列表点击“应用”
2. 进入应用确认页，展示模板信息和预计影响商品数
3. 选择应用方式（仅补充空白 / 强制覆盖）
4. 选择低于成本价的处理策略（跳过 / 按成本价兜底 / 整单拒绝）
5. 确认后提交表单
6. 系统遍历该分类下所有商品，对每个 SKU 执行：
   - 检查是否已有会员价，已有且为“仅补充空白”则跳过
   - 检查价格基准是否存在，缺失则跳过
   - 对模板中每个设置了系数的会员组：
     - 按系数计算该组的会员价
     - 保本校验，按运营选择的策略处理
   - 写入该 SKU 的 `group_prices`
7. 遍历完成后写入应用日志
8. 页面提示结果并跳转到日志页

**执行方式：**

- 初期商品少时同步执行。
- 如果后续单个分类下商品数超过 500，建议改为后台任务。
- 具体采用哪种方式，根据项目实际情况决定。


## 十一、低于成本价的处理策略

应用模板时，如果计算出的会员价低于成本价，按运营选择的策略处理：

| 策略 | 行为 | 适用场景 |
|---|---|---|
| `skip`（默认） | 跳过该会员组，不写入该组，记录异常 | 安全优先 |
| `floor_to_cost` | 该会员组价格替换为成本价，继续写入，记录兜底 | 所有会员组都要有价格，但保本优先 |
| `reject_all` | 整单拒绝，不写入任何数据，返回错误提示 | 应用前必须确保所有商品都不亏本 |

**默认策略：** `skip`。


## 十二、复制模板说明

**复制流程：**

1. 运营在模板列表点击“复制”
2. 系统复制该模板的计价基准、会员组系数
3. 新模板名称自动加后缀，如“塑料制品会员价 - 副本”
4. 复制后跳转到编辑页，让运营修改名称和系数
5. 复制后不自动应用，需要运营手动点击“应用”

**关键点：** 复制只复制模板本身，不影响商品数据。


## 十三、删除模板说明

**删除流程：**

1. 运营在模板列表点击“删除”
2. 弹出确认弹窗，提示“删除后不影响已应用的会员价数据”
3. 确认后删除模板

**关键点：**

- 删除只删除模板本身，不影响商品数据。
- 应用日志中保留 `template_name` 冗余字段，即使模板被删，日志仍可读。


## 十四、回滚方案说明

**第一版不做回滚，但预留数据结构。**

- 在应用日志中增加 `snapshot` 字段，暂时不填，预留位置。
- 如果后续需要回滚，只需在应用时把原始数据填入 `snapshot`，再增加一个回滚路由即可。
- 回滚只对强制覆盖模式生效，仅补充空白模式不需要回滚。


## 十五、校验规则

**模板保存时校验：**

- 模板名称不能为空
- 必须选择适用分类
- 计价基准必须合法
- 至少有一个会员组设置了系数
- 系数必须为正数
- 基于成本价加价率时，所有系数 ≥ 1
- 基于零售价折扣率时，所有系数 ≤ 1

**应用时校验：**

- 计算出的会员价低于成本价 → 按运营选择的策略处理


## 十六、关键设计点

**第一，模板不能存固定价格。** 必须存系数（折扣率或加价率），应用时按每个商品自己的价格基准计算。

**第二，会员组是系统固定集合。** 表单直接列出所有会员组，运营给需要设置的组填系数，留空表示该模板不设置这个组的会员价。不需要“添加会员组”按钮。

**第三，两种计价基准并存。** 运营创建模板时选择一种，不同模板可以用不同基准。

**第四，预览是保存前的必要辅助。** 运营在保存前看到示例商品的每个会员组计算结果。

**第五，应用日志必须记录。** 日志中冗余存 `template_name`、`category_name`、`created_by_name`，避免模板删除后日志不可读。

**第六，低于成本价必须有明确策略。** 默认跳过并记录异常，同时提供“按成本价兜底”和“整单拒绝”作为可选策略。

**第七，数据模型不变。** 模板只是计算工具，应用后商品数据里存的仍然是固定价格。

**第八，HTML 文件统一放子目录。** 会员价模板的 5 个 HTML 文件放在 `shop_admin/member_price_template/` 子目录下，文件名使用短名称。

**第九，公共导航统一。** 公共导航文件放在 `shop_admin/_price_template_nav.html`，阶梯价模板和会员价模板共用，通过 `active_tab` 控制高亮。


## 十七、一句话总结

**新增“会员价模板”功能，运营按分类创建模板，选择计价基准（零售价折扣率 或 成本价加价率），给系统已有的会员组填写系数，保存前可预览示例商品的每个会员组计算结果。应用时按每个商品自己的价格基准计算每个会员组的固定价格，低于成本价时按策略处理。支持复制模板、查看应用日志、追溯异常明细。HTML 文件统一放在 `shop_admin/member_price_template/` 子目录下，文件名使用短名称。公共导航文件放在 `shop_admin/_price_template_nav.html`，阶梯价模板和会员价模板共用。模板只是计算工具，不改变数据模型，不影响价格计算逻辑。**
