# 商城定价体系完整流程（基于 CMS + MongoDB 实际结构）

## 一、核心设计原则

**一套商品数据，两个价格维度，动态解析，取低生效，底价兜底。**

- **身份维度**：会员组价格（`group_prices`），解决“谁买”的问题。
- **数量维度**：批量阶梯价（`group_qty_prices`），解决“买多少”的问题。
- 两个维度独立生效，最终取所有有效候选中的最低价。


## 二、数据模型（基于实际结构）

### 1. 商品表 `NewsContent`

| 字段 | 说明 |
|---|---|
| `column_10` | SKU 数组，每个元素为一个 SKU |
| 其他字段 | 商品名称、图片、描述等 |

### 2. SKU 结构（`column_10` 数组的每个元素）

```json
{
    "sku": "GX-IR1435-002",
    "productId": "ccabbfdd0d3ae215bcdb9695ea57fe17",
    "name": "Original / Green · Approx. 40,000 pages.",
    "image": "/products/gx-ir1435-002/1.jpg",
    "weight": 0,
    "stock": 1000000,

    "marketPrice": 20,
    "costPrice": 14,

    "group_prices": [
        {
            "group_id": "66b4926df455dd91ca3de33e",
            "group_name": "svip",
            "price": 16
        },
        {
            "group_id": "66b4924ff455dd91ca3de33d",
            "group_name": "vip",
            "price": 18
        }
    ],

    "group_qty_prices": [
        {
            "min_qty": 10,
            "max_qty": 49,
            "price": 16
        },
        {
            "min_qty": 50,
            "max_qty": 99,
            "price": 12
        }
    ]
}
```

### 3. 字段说明

| 字段 | 层级 | 说明 |
|---|---|---|
| `marketPrice` | SKU 级 | 零售标价，所有价格的回退锚点 |
| `costPrice` | SKU 级 | 成本价，仅用于结算底价校验 |
| `group_prices` | SKU 级 | 会员组价格数组，身份权益，可选覆盖 |
| `group_qty_prices` | SKU 级 | 批量阶梯价数组，数量权益，全平台通用 |
| `stock` | SKU 级 | 库存 |

**关键点**：价格全部挂在 **SKU 级**，不是商品级。同一个商品的不同规格，可以有不同的 `marketPrice`、`costPrice`、`group_prices`、`group_qty_prices`。


## 三、价格计算流程

### 触发时机

商品详情页、购物车、结算页均执行同一套逻辑，保证价格一致。

### 计算步骤

```
输入：user（当前用户）、sku（选中的 SKU）、quantity（采购数量）

第一步：确定当前用户所在会员组
        未登录 / 零售用户 → 默认零售组（无 group_prices 匹配）

第二步：收集候选价格

        候选 A：会员组价格
        遍历 sku.group_prices
        找到 group_id == 当前用户 group_id 的项
        有 → 取 price 加入候选集合

        候选 B：批量阶梯价
        遍历 sku.group_qty_prices
        按 quantity 匹配档位：
          quantity >= min_qty 且 (max_qty 为空 或 quantity <= max_qty)
        落入某档 → 取 price 加入候选集合
        未达第一档 MOQ → 不加入候选

        候选 C：基础零售价
        sku.marketPrice 始终作为兜底候选

第三步：取最低价
        final_price = min(所有有效候选)

第四步：底价校验（结算环节执行）
        if final_price < sku.costPrice:
            final_price = sku.costPrice
```

### 关键规则

- **会员组价格是身份价**，买 1 件也生效，前提是用户属于该组。
- **阶梯价是数量价**，未达 MOQ 不生效，回退到会员组价格或基础价。
- **取低生效**：会员价与阶梯价同时存在时，取较低者。
- **底价校验**：最终价低于成本价时，按成本价结算（可在后台设置是否保本，默认是）。
- **SKU 独立计算**：价格全部在 SKU 级，不同 SKU 独立计算，不跨 SKU 合并数量。


## 四、会员组进入门槛

会员组价格本身不设 MOQ，但“进入批发会员组”由管理员在 CMS 后台设置：

```
【登录后台】->【管理用户】->【修改用户】->【修改会员组】
```

- 一旦加入，买 1 件也按会员组价格。
- 阶梯价的 MOQ 保留，作为“买更多、更便宜”的额外激励，对所有人开放。


## 五、配置示例

**商品：不锈钢保温杯**

SKU：`GX-IR1435-002`

- `marketPrice`：59 元
- `costPrice`：28 元
- `group_prices`：

| group_name | group_id | price |
|---|---|---|
| 批发会员 | xxx | 45 |

- `group_qty_prices`：

| min_qty | max_qty | price |
|---|---|---|
| 50 | 199 | 42 |
| 200 | 999 | 38 |
| 1000 | 留空 | 35 |

**不同客户、不同数量的最终成交价：**

| 客户身份 | 采购数量 | 会员价 | 阶梯价 | 最终成交价 |
|---|---|---|---|---|
| 零售用户 | 1 件 | 无 | 无 | 59（基础价） |
| 零售用户 | 30 件 | 无 | 无（未达 MOQ） | 59（基础价） |
| 零售用户 | 50 件 | 无 | 42 | **42（阶梯价）** |
| 零售用户 | 500 件 | 无 | 38 | **38（阶梯价）** |
| 批发会员 | 1 件 | 45 | 无（未达 MOQ） | **45（会员价）** |
| 批发会员 | 30 件 | 45 | 无（未达 MOQ） | **45（会员价）** |
| 批发会员 | 100 件 | 45 | 42 | **42（取低）** |
| 批发会员 | 500 件 | 45 | 38 | **38（取低）** |
| 批发会员 | 2000 件 | 45 | 35 | **35（取低）** |

若某 SKU 会员组价格为 30 元，低于所有阶梯档，则无论买多少都按 30 元结算。


## 六、商品详情页价格展示

### 页面加载（Flask 模板渲染）

```
浏览器请求页面 → Flask 渲染 HTML
HTML 包含：
  - 商品名称、图片、描述
  - SKU 列表、规格属性
  - 基础价（作为兜底展示）
  - 价格展示区域（先展示基础价或“加载中”）
```

### 异步加载价格规则

```
GET /shop/api/product/{id}/prices
返回：当前用户可见的价格规则

{
  "product_id": "ccabbfdd0d3ae215bcdb9695ea57fe17",
  "skus": [
    {
      "sku": "GX-IR1435-002",
      "marketPrice": 20,
      "costPrice": 14,
      "member_price": 16,
      "member_group": "svip",
      "qty_prices": [
        {"min_qty": 10, "max_qty": 49, "price": 16},
        {"min_qty": 50, "max_qty": 99, "price": 12}
      ]
    }
  ]
}
```

**服务端身份过滤**：

- 零售用户：只返回 `marketPrice`，不返回 `group_prices` 和 `group_qty_prices`
- 批发会员：返回 `marketPrice` + 该用户所在组的 `member_price` + `qty_prices`

### 前端处理

```
1. 单 SKU：
   - 收到价格规则后，直接计算精确单价并展示
   - 不需要规格选择器，不需要价格区间

2. 多 SKU：
   - 收到价格规则后，遍历所有 SKU，对每个 SKU 取 min(会员价, 阶梯价, 基础价)
   - 取整体最小值和最大值，展示价格区间
   - 用户选择 SKU → 前端用缓存规则本地计算精确价格 → 立即展示

3. 用户修改数量：
   - 前端用已缓存的 qty_prices 本地重新匹配阶梯档位
   - 更新单价展示
   - 展示“再买 X 件可享批发价 Y 元”

4. 加入购物车：
   - 后端重新计算价格，与前端传的价格比对
   - 不一致则以后端为准，并记录日志
```

**不需要的接口**：

- `GET /shop/api/product/{id}/sku/{sku_id}/price`：`/prices` 已返回所有 SKU 对当前用户可见的规则，前端本地计算即可。
- 修改数量时的校验接口：详情页的数量变化只是展示层，本地计算最快。真正的校验在加购、结算、提交订单三个节点完成。


## 七、购物流程

### 第 1 步：商品详情页 → 加入购物车

**页面加载**：Flask 模板渲染商品信息 + SKU 列表 + `marketPrice`（兜底展示）。

**异步请求**：

```
GET /shop/api/product/{id}/prices
```

前端拿到规则后：

- 单 SKU：直接计算并展示精确价格
- 多 SKU：计算价格区间，切换 SKU 时本地计算
- 修改数量：本地重新匹配阶梯档位

**加购校验**（宜松）：

- 商品是否上架 → 未上架则拦截
- 库存是否 > 0 → 无库存则拦截
- 是否超限购 → 超限则提示

**不做的事**：不锁库存、不锁价格。

**加购时后端重新计算价格**，与前端传的价格比对，不一致以后端为准。


### 第 2 步：购物车页 → 展示商品列表及价格

**每次加载、数量变更、登录状态变更，重新执行价格计算。**

**展示内容**：

| 展示项 | 说明 |
|---|---|
| 商品名称、规格、图片 | 基本信息 |
| 单价 | 取低后的最终单价 |
| 价格来源 | 如“会员价”“已享批发价 10-49 件档”“零售价” |
| 数量 | 可修改 |
| 小计 | 单价 × 数量 |
| 优惠引导 | 如“再买 X 件可享批发价 Y 元” |
| 失效标记 | 已下架 / 库存不足的商品标记并允许删除 |

**校验**：重新校验商品上架状态、库存 > 0。不锁库存、不锁价格。


### 第 3 步：提交购物车 → 进入结算页

**定位**：预计算，展示最终应付金额，但不锁价、不锁库存。

**计算内容**：

```
商品总价 = Σ(各 SKU 最终单价 × 数量)
运费 = 订单金额 >= 包邮门槛 ? 0 : 统一运费
应付总额 = 商品总价 + 运费
```

**校验内容**：商品是否仍上架、库存是否 >= 购买数量、收货地址是否完整。

**不做的事**：不锁库存、不锁价格，用户仍可返回购物车修改。


### 第 4 步：提交订单 → 锁价、校验库存、生成订单

**执行顺序**：

```
1. 最后一次校验商品上架状态
2. 校验库存 >= 购买数量
3. 扣减库存（原子操作，防并发超卖）
4. 重新执行价格计算
   final_price = min(会员价, 阶梯价, marketPrice)
5. 底价校验：if final_price < costPrice → final_price = costPrice
6. 计算运费
   运费 = 订单金额 >= 包邮门槛 ? 0 : 统一运费
7. 写入订单快照
8. 订单状态：待支付
9. 选择支付方式（作为订单字段记录）
```

**订单快照必须记录**：

| 快照字段 | 说明 |
|---|---|
| 商品 ID、名称 | 防止商品后续改名 |
| SKU | 规格标识 |
| 下单时单价 | 最终成交单价 |
| 数量 | 采购数量 |
| 价格来源 | 会员价 / 阶梯价 / 基础价 / 成本价 |
| 运费 | 实际运费金额 |
| 应付总额 | 最终金额 |

**锁价**：订单一旦生成，价格锁定，后续运营改价不影响已生成订单。

**库存策略**：下单即扣 + 超时释放。


### 第 5 步：支付订单 → 支付成功，状态流转

**支付成功后**：

- 确认库存扣减（下单即扣模式下无需再操作）
- 记录支付流水
- 订单状态：待支付 → 待发货
- 触发发货流程
- 通知用户和运营

**支付失败或超时**：

- 订单保持“待支付”
- 超时后释放库存，订单关闭


## 八、接口设计

| 接口 | 时机 | 返回内容 |
|---|---|---|
| `GET /shop/api/product/{id}/prices` | 商品详情页加载时 | 当前用户可见的价格规则（marketPrice + 会员价 + 阶梯价） |

**身份过滤在服务端完成**：零售用户只返回 `marketPrice`，批发会员返回 `marketPrice` + `member_price` + `qty_prices`。


## 九、运费计算

```
calculate_shipping(order_amount) → {
    shipping_fee,
    is_free
}

if (order_amount >= free_shipping_threshold) {
    shipping_fee = 0
} else {
    shipping_fee = flat_shipping_fee
}
```

**后台配置项**：

| 配置项 | 说明 | 示例 |
|---|---|---|
| `free_shipping_threshold` | 包邮门槛 | 500 |
| `flat_shipping_fee` | 统一运费 | 20 |


## 十、校验分布总览

| 校验项 | 加购时 | 购物车 | 结算页 | 提交订单 |
|---|---|---|---|---|
| 商品是否上架 | ✅ 拦截 | ✅ 标记 | ✅ 拦截 | ✅ 拦截 |
| 库存 > 0 | ✅ 拦截 | ✅ 标记 | — | — |
| 库存 >= 购买数量 | — | — | ✅ 校验 | ✅ 校验 + 扣减 |
| 限购 | ✅ 提示 | ✅ 提示 | ✅ 校验 | ✅ 校验 |
| 价格重新计算 | ✅ | ✅ | ✅ | ✅ 锁价 |
| 底价校验 | — | — | — | ✅ |
| 锁库存 | — | — | — | ✅ |
| 锁价格 | — | — | — | ✅ |


## 十一、库存与一致性

- 无论展示几种价格，背后是**同一个库存实体**。
- 不为批发单独建商品，不单独扣库存。
- 避免库存割裂、超卖风险和报表混乱。


## 十二、一句话总结

**商品价格全部挂在 SKU 级：`marketPrice` 为零售标价，`costPrice` 为成本价，`group_prices` 为会员组身份价，`group_qty_prices` 为全平台数量阶梯价。计算时取所有有效候选中的最低价，低于成本价则按成本价结算。身份决定基准，数量决定激励，取低生效，底价兜底。全链路共用同一个价格计算函数，商品详情页价格走异步接口 `GET /shop/api/product/{id}/prices` 按用户身份过滤返回。**
