# 模块系统

模块系统用于向系统添加独立的功能单元。每个模块是一个自包含的 Python 包，
拥有自己的路由、模板、静态文件和配置。模块之间不应相互依赖，如需通讯请通过信号（事件）机制。

---

## 一、目录结构

所有模块统一放在项目根目录的 `eb_modules/` 下，每个模块是一个独立的目录（Python 包）：

```
eb_modules/
├── credits_sys/          # 积分管理系统（示例模块）
│   ├── __init__.py       # 模块入口（必需）
│   ├── pages.py          # 前台/后台页面路由
│   ├── apis.py           # API 路由
│   ├── datas/            # 数据访问层
│   │   └── credits_plan.py
│   ├── templates/        # 模块模板文件
│   │   ├── credits_index.html
│   │   └── credits_admin/
│   └── static/           # 模块静态文件（JS/CSS/图片）
├── eb_shop/              # 商城系统（示例模块）
├── aitanqin/             # AI 音乐相关（示例模块）
└── app_apis/             # APP/客户端 API 集（示例模块）
```

### 目录约定

| 路径 | 必需 | 说明 |
|------|------|------|
| `__init__.py` | ✅ 是 | 模块入口，定义 `module_init` 函数 |
| `templates/` | ❌ 否 | 模块专用的 Jinja2 模板文件 |
| `static/` | ❌ 否 | 模块专用的静态文件（JS、CSS、图片） |
| `datas/` | ❌ 否 | 数据访问层（BLL），按需组织 |
| `shop_controls/` | ❌ 否 | 模型控件（后台编辑器的自定义组件） |

## 二、模块入口（__init__.py）

### 2.1 核心函数

系统启动时会自动扫描 `eb_modules/` 下每个子目录，加载其 `__init__.py`，
并在其中查找 **`module_init`** 函数。此函数是模块的初始化入口，名称不可更改。

```python
module_init(app: Flask, model: ModuleInfo) -> None
```

- `app`：当前 Flask 应用实例
- `model`：当前模块的 `ModuleInfo` 实例，包含模块元信息和配置读写方法

### 2.2 装饰器 @module_attribute

`module_init` 必须使用 `@module_attribute` 装饰器注册模块元信息。

```python
from .. import module_attribute, ModuleInfo

@module_attribute(
    name='模块名称',           # 必填：后台列表中显示的名称
    info='模块功能说明',         # 必填：模块功能介绍
    admin_url='/admin/path',   # 后台管理入口 URL（没有则传空字符串 ""）
    settings_temp=None,        # 配置模板 HTML（没有则传 None）
    author='作者名',            # 必填：作者标识
    enable=True,               # 是否启用（False 则不加载）
    version=1.0,               # 版本号
    priority=999               # 优先级（数字越小越靠前）
)
def module_init(app: Flask, model: ModuleInfo):
    ...
```

**参数说明：**

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `name` | `str` | — | 模块名称，显示在后台模块列表中 |
| `info` | `str` | — | 模块功能介绍 |
| `admin_url` | `str` | — | 后台管理入口地址（如 `"/credits/credits_orders"`），没有则留空 |
| `settings_temp` | `str \| None` | — | 配置表单的 HTML 模板字符串（见下文"模块配置"） |
| `author` | `str` | — | 作者标识 |
| `enable` | `bool` | `True` | 是否启用，设为 `False` 该模块完全不加载 |
| `version` | `float` | `1.0` | 版本号 |
| `priority` | `int` | `999` | 排序优先级，数字越小在列表中越靠前 |
| `config_fields` | `dict \| None` | `None` | **可选**。字段类型声明，如 `{'credits_price': 'int'}`。设置后配置保存时会自动做类型转换，详见下文"config_fields 说明"。 |

## 三、蓝图（Blueprint）的创建与注册

模块通过 Flask 的 **Blueprint** 来组织路由。建议在 `__init__.py` 中创建蓝图，在 `module_init` 中注册到 app。

### 3.1 页面蓝图

```python
from flask import Blueprint

module_url_prefix = "/my_module"

bp_page = Blueprint(
    'bp_my_module_pages',
    __name__,
    template_folder='templates',    # 指向模块下的 templates 目录
    static_folder='static',          # 指向模块下的 static 目录
    static_url_path='/',             # 静态文件 URL 前缀（固定为 /）
    url_prefix=module_url_prefix     # 页面访问前缀
)
```

### 3.2 API 蓝图

如果模块需要提供 API，建议单独创建一个 API 蓝图：

```python
bp_api = Blueprint(
    'bp_my_module_apis',
    __name__,
    url_prefix=f"{module_url_prefix}/api/"
)
```

API 蓝图的 `url_prefix` 建议与页面蓝图保持一致的模块前缀。

### 3.3 完整初始化示例

```python
from flask import Flask, Blueprint
from .. import module_attribute, ModuleInfo

module_url_prefix = "/music_ai"

bp_page = Blueprint('bp_music_pages', __name__,
                    template_folder='templates',
                    static_folder='static',
                    static_url_path='/',
                    url_prefix=module_url_prefix)

bp_api = Blueprint('bp_music_apis', __name__,
                   url_prefix=f"{module_url_prefix}/api/")

@module_attribute('AI 音乐', '用 AI 生成音乐', '/music_ai/tasks', None, 'ebsite')
def module_init(app: Flask, model: ModuleInfo):
    # 1. 读取模块配置
    config = model.get_configs()

    # 2. 将配置注入蓝图上下文
    bp_page.config = config
    bp_api.config = config

    # 3. 注册蓝图
    app.register_blueprint(bp_page)
    app.register_blueprint(bp_api)

    # 4. 注册信号监听（可选）
    # content_saving.connect(on_content_saving)

# 5. 在底部导入路由模块，确保蓝图上的路由装饰器能正确绑定
from . import pages
from . import apis
```

> ⚠️ **顺序重要**：`from . import pages` 等导入语句必须放在文件底部，
> 因为 `quote_pages.py` 中会引用上面定义的蓝图对象（如 `bp_page`）。

## 四、页面的开发

建议在单独的 `quote_pages.py` 中编写页面路由。模块的模板系统与系统模板互通：

- 系统模板搜索路径优先，模块模板其次
- 模块模板中可以直接引用系统母版页和系统静态资源
- 模块自身的静态文件放在 `static/` 目录下，蓝图中 `static_url_path='/'` 保证了引用路径简洁

### 4.1 前台页面示例

```python
from eb_modules.my_module import bp_page

@bp_page.route('/list')
def item_list():
    return render_template("my_module/list.html")
```

### 4.2 后台管理页面示例

后台管理页面需要使用 `@check_admin_login` 装饰器确保登录权限：

```python
from decorators import check_admin_login
from entity.user_token import UserToken

@bp_page.route('/orders')
@check_admin_login
def orders(admin_token: UserToken):
    # admin_token 包含当前登录管理员信息
    return render_template("my_module_admin/orders.html")
```

## 六、模块配置

### 6.1 配置表单模板

如果模块需要后台配置参数，在 `__init__.py` 中定义 `settings_temp` 变量：

```python
settings_temp = '''
<div class="mb-3">
    <label>积分定价（1 人民币可购买多少积分）</label>
    <input name="credits_price" value="{{model.credits_price}}"
           type="number" class="form-control" required>
</div>
<div class="mb-3">
    <label>支付回调域名</label>
    <input name="pay_back_url" value="{{model.pay_back_url}}"
           class="form-control">
</div>
'''
```

> 模板采用 Jinja2 语法，`{{model.xxx}}` 用于回显已保存的值。
> 系统会自动渲染此模板并处理配置的保存与读取。

### 6.2 在代码中读取配置

在 `module_init` 中通过 `model.get_configs()` 读取：

```python
def module_init(app: Flask, model: ModuleInfo):
    config = model.get_configs()        # 返回 dict
    credits_price = config.get('credits_price', 10)
    pay_back_url = config.get('pay_back_url')
```

### 6.3 在页面/API 中读取配置

配置注入蓝图后，可通过蓝图对象的 `config` 属性访问：

```python
from eb_modules.my_module import bp_page

@bp_page.route('/some_page')
def some_page():
    credits_price = bp_page.config.get('credits_price')
```

### 6.4 config_fields 说明（可选）

`config_fields` 是 `@module_attribute` 装饰器上的一个**可选参数**，用于声明模块配置中每个字段的类型。

#### 有什么用？

| 不设置 config_fields | 设置 config_fields |
|---|---|
| 表单提交的 `"10"` 以字符串存入 MongoDB | 自动转为 `10`（int）存入 MongoDB |
| 代码中读取后需要手动 `int(config['credits_price'])` | 读取时已是正确类型，无需额外转换 |
| 后续系统想扩展配置校验/导出等功能时缺少字段清单 | 字段清单明确，便于后续功能扩展 |

#### 示例

```python
@module_attribute(
    '积分管理系统',
    '扩展系统的积分管理功能',
    "/credits/credits_orders",
    settings_temp,
    'ebsite',
    config_fields={
        'credits_price': 'int',       # 数字：自动从 "10" 转为 10
        'pay_back_url': 'str',        # 字符串：保持原样
        'enable_debug': 'bool',       # 布尔值："true"/"1"/"yes" → True
    }
)
def module_init(app: Flask, model: ModuleInfo):
    ...
```

#### 支持的类型

| 类型标识 | Python 类型 | 说明 |
|---------|-------------|------|
| `'str'` | `str` | 字符串，保持原样 |
| `'int'` | `int` | 整数，如 `"10"` → `10` |
| `'float'` | `float` | 浮点数，如 `"3.14"` → `3.14` |
| `'bool'` | `bool` | 布尔值，`"true"`/`"1"`/`"yes"`（不区分大小写）→ `True` |

#### 注意事项

- **完全可选**：不设置时行为与之前完全一致，不会影响现有模块
- **不改渲染**：`settings_temp` 的 HTML 模板写法不变，`config_fields` 只影响保存时的类型转换
- **转换失败**时保留原始值，不会导致保存出错

## 八、模块间通信（信号机制）

模块之间**不应直接 import**，而是通过 Flask 信号（Signal）实现松耦合通信。

### 8.1 监听信号

```python
from signals import content_saving, pay_saved_successful

def module_init(app: Flask, model: ModuleInfo):
    content_saving.connect(on_content_saving)
    pay_saved_successful.connect(on_pay_saved_successful)

def on_content_saving(model) -> (bool, str):
    # 内容保存前的处理逻辑
    return True, 'success'

def on_pay_saved_successful(model) -> (bool, str):
    # 支付成功后的处理逻辑
    return True, 'success'
```

### 8.2 可用信号列表

请参考 `doc/可监听的信号(事件).md` 获取系统当前支持的所有信号及其参数说明。

## 九、开发规范与最佳实践

### 目录组织建议

```
my_module/
├── __init__.py       # 蓝图创建 + module_init
├── pages.py          # 页面路由
├── apis.py           # API 路由
├── datas/            # 数据访问层
├── templates/        # 模板文件
├── static/           # 静态文件
└── shop_controls/    # 模型控件（如有）
```

### 编码规范

- `module_init` 函数名不可更改，系统通过此名称识别模块入口
- 页面/API 文件的导入语句统一放在 `__init__.py` **底部**
- 模块间不应直接 import，如有需要请使用信号机制
- 后台页面必须添加 `@check_admin_login` 装饰器
- 蓝图名称（`Blueprint` 的第一个参数）需保持唯一，建议以 `bp_模块名_pages` / `bp_模块名_apis` 命名

### 模板与静态文件

- 模块模板中可以自由使用系统母版页和系统静态资源
- 系统模板搜索路径优先于模块模板
- `static_url_path='/'` 使静态文件可通过 `/your_static_file.js` 直接访问

## 十、常见问题

### Q：模块加载失败怎么办？

检查以下常见原因：
1. `__init__.py` 中是否定义了 `module_init` 函数
2. `module_init` 是否使用了 `@module_attribute` 装饰器
3. `module_init` 函数名是否拼写正确（注意大小写）
4. 蓝图的 `template_folder` 是否指向了正确的目录

### Q：如何临时关闭一个模块？

在 `@module_attribute` 装饰器中将 `enable=False`，或直接删除模块目录。

### Q：如何让配置修改后立即生效？

后台保存配置后会自动触发热更新回调，模块蓝图的 `config` 对象会立即刷新，**无需重启应用**。

如果你的模块在 `module_init` 中除了读取配置之外还有其他初始化逻辑（如连接外部服务），
请在 `module_init` 中通过 `model.on_config_changed(callback)` 注册一个配置刷新回调来更新这些依赖：

```python
def module_init(app: Flask, model: ModuleInfo):
    config = model.get_configs()
    bp_page.config = config

    # 如果模块有其他依赖配置的运行时对象，在这里刷新
    def refresh_config(saved_config):
        bp_page.config = saved_config
        # 如有其他依赖配置的对象也在此更新
    model.on_config_changed(refresh_config)

    app.register_blueprint(bp_page)
```
