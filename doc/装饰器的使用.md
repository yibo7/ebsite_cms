### 一、会话追踪

> `check_session(func)` —— 无参数，直接装饰

为匿名用户设置 `session_id` Cookie，仅当请求中不存在时生成。

**注意事项：**
- 装饰器必须放在**最内层**（最贴近视图函数的位置），确保被装饰函数的返回值是一个 **Response 对象**。
- 如果返回 `render_template()` 或 `redirect()` 等 Flask 自动包装的响应，Flask 内部会将其转为 Response，所以不影响使用。

**示例：**

```python
@app.route('/')
@check_session
def index():
    return render_template('index.html')
```

### 二、后台操作审计日志

> `admin_action_log(title: str)`

在视图函数执行前自动记录一条后台操作日志到数据库（`SiteLog` 集合）。

| 参数 | 类型 | 说明 |
|------|------|------|
| `title` | `str` | 日志标题，如 `"删除文章"`、`"修改用户"` |

**自动采集的信息：**
- 函数名称 + 调用参数
- 当前用户（通过 `g.u` 获取，安全兼容不存在的情况）
- 完整请求 URL + 客户端 IP
- 日志写入失败不影响业务（**try/except 兜底**）

**示例：**

```python
@admin_action_log("删除用户")
def delete_from_page(self, s_id):
    if s_id:
        a_id = s_id.split(',')
        if 'on' in a_id:
            a_id.remove('on')
        self.delete_by_ids(a_id)
```

### 三、IP 频率限制

> `rate_limit_ip(limit: int, per_minutes: int)`

限制某个 IP 在指定时间窗口内的请求次数。

| 参数 | 类型 | 说明 |
|------|------|------|
| `limit` | `int` | 允许的最大请求次数 |
| `per_minutes` | `int` | 时间窗口（分钟） |

**实现说明：**
- 基于缓存**原子自增**（`cache.incr`），**无并发竞态条件**。
- 超过限制返回 `401` + `"Rate limit exceeded"`。

**示例：**

```python
# 1 分钟内只允许 10 次
@rate_limit_ip(10, 1)

# 5 分钟内只允许 100 次
@rate_limit_ip(100, 5)
```

### 四、API Token 验证

> `check_token(is_use_token: bool = True)`

验证请求头 `x-api-key` 中的 Token 是否有效。适用于移动端 APP 或第三方客户端请求 API 的场景。

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `is_use_token` | `bool` | `True` | 是否将 Token 数据注入视图函数 |

- **`is_use_token=True`（默认）**：注入 `token` 关键字参数，视图函数需声明接收。
- **`is_use_token=False`**：仅验证不注入。

**开发测试模式：**
当 `current_app.debug = True` 且配置了 `DEBUG_TOKEN` 环境变量时，可通过该值绕过 Token 验证。

**示例：**

```python
# 方式一：验证并接收 Token
@api_app_blue.route('create_music', methods=['POST'])
@check_token()
def create_music(token: UserToken):
    ...

# 方式二：仅验证，不接收 Token
@api_app_blue.route('create_music', methods=['POST'])
@check_token(False)
def create_music():
    ...
```

### 五、请求签名验证

> `check_sign(check_replay: bool = False)`

验证请求参数的 MD5 签名，可选启用防重放攻击。

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `check_replay` | `bool` | `False` | 是否启用防重放 |

**签名算法：**

1. 收集所有请求参数（不含 `sign`）
2. 按 Key 的字典序升序排列
3. 拼接为 `k1=v1&k2=v2&...&appkey=APP_KEY`
4. 计算整体字符串的 **MD5** 值
5. 与请求中的 `sign` 参数比对

**防重放机制（`check_replay=True` 时）：**
- 要求额外携带 `nonce`（随机字符串）和 `time`（Unix 时间戳）参数
- `nonce` 使用后 10 分钟内不可重复使用
- 时间戳与服务端时间偏差超过 10 分钟拒绝

**示例：**

```python
# 仅验证签名
@check_sign()

# 验证签名 + 防重放
@check_sign(True)
```

### 六、网站 Key MD5 验证

> `verify_site_key_md5(func)`

验证 API 路由参数中的 `site_key_md5` 是否与服务端配置的 `SiteKey` 一致。用于多站点场景。

- 从路由参数 `kwargs` 中提取 `site_key_md5`
- 读取 `current_app.config['SiteKey']`
- 计算 MD5 比对

**示例：**

```python
@app.route('/api/data/<md5:site_key_md5>')
@verify_site_key_md5
def api_data(site_key_md5):
    ...
```

### 七、智能图片验证码（阈值触发）

> `check_img_code(max_requests: int, time_limit: int = 60)`

超过指定时间窗口内的请求阈值后，强制要求图片验证码。

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `max_requests` | `int` | — | 触发验证码的请求次数阈值 |
| `time_limit` | `int` | `60` | 时间窗口（分钟） |

**工作机制：**

1. `time_limit` 分钟内请求数不超过 `max_requests` → 不要求验证码
2. 超过阈值后 → 后续请求必须携带 `code` + `code_key` 参数
3. 验证码错误 → 限制时间**递进式延长**（原过期时间的 3 倍）
4. 验证码正确 → **清空限制缓存**，恢复正常访问

**示例：**

```python
# 60 分钟内超出 10 次后要求验证码
@check_img_code(10)

# 1 分钟内超出 2 次后要求验证码
@check_img_code(2, 1)
```

### 九、手机 / 邮箱验证码验证

> `check_mobile_email_code(func)`

验证用户提交的手机或邮箱安全码。

- 从请求参数获取 `code` 和 `account`
- 通过 `MobileCode` 校验
- 验证通过后，已验证的账号通过 **`g.account`** 传递给视图函数

**示例：**

```python
@check_mobile_email_code
def bind_mobile():
    account = g.account  # 已验证的手机号或邮箱
    ...
```

### 十、后台登录验证

> `check_admin_login(func)`

验证当前请求是否来自已登录的后台管理员。

- **页面请求（未登录）** → 重定向到后台登录页
- **API 请求（未登录）** → 返回 401 JSON（通过 `Accept: application/json` 或 `X-Requested-With` 自动识别）
- **已登录** → 注入 `admin_token` 关键字参数

**示例：**

```python
@admin_router.route('/user/list')
@check_admin_login
def user_list(admin_token: UserToken):
    ...
```

### 十一、前端登录验证

> `check_user_login(func)`

验证当前请求是否来自已登录的前端用户。行为逻辑与 `check_admin_login` 一致。

- **页面请求（未登录）** → 重定向到用户登录页
- **API 请求（未登录）** → 返回 401 JSON
- **已登录** → 注入 `user_token` 关键字参数

**示例：**

```python
@app.route('/user/profile')
@check_user_login
def profile(user_token: UserToken):
    ...
```

### 十二、后台权限检查

> `require_permission(pos_id: str)`

检查当前管理员是否拥有指定的后台权限标识。**必须与 `@check_admin_login` 配合使用。**

| 参数 | 类型 | 说明 |
|------|------|------|
| `pos_id` | `str` | 权限标识，如 `"article:delete"`、`"user:edit"` |

**权限校验逻辑：**
1. 从 `admin_token.group_id` 获取角色 ID
2. 查询 `AdminRole` 集合获取角色的权限列表 `pos_id`
3. 检查 `pos_id` 是否在列表中
4. 权限不足 → 返回 401 + 明确的 `"权限不足，需要「xxx」"` 信息
5. 未搭配 `@check_admin_login` → 抛出 `RuntimeError`（快速失败）

**示例：**

```python
@admin_router.route('/article/delete/<id>')
@check_admin_login
@require_permission('article:delete')       # ← 权限检查
def article_delete(id):
    ...

@admin_router.route('/user/edit/<id>')
@check_admin_login
@require_permission('user:edit')            # ← 权限检查
def user_edit(id):
    ...
```

### 十三、防重复提交

> `no_repeat_submit(key_prefix: str = '', lock_seconds: int = 3)`

防止用户在短时间内重复提交相同请求。

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `key_prefix` | `str` | `''` | 业务前缀，建议传入（如 `"article_save"`） |
| `lock_seconds` | `int` | `3` | 锁定时间（秒），到期自动释放 |

**锁定规则：**

```
锁键 = no_repeat_{key_prefix}_{用户ID/IP}_{函数名}
```

- 用户标识优先使用已登录用户 ID，回退到 IP
- `try/finally` 保证正常完成后**立即释放锁**，不阻塞后续操作
- 被拦截 → 返回 401 + `"操作过于频繁，请稍后再试"`

**示例：**

```python
@admin_router.route('/article/save', methods=['POST'])
@check_admin_login
@no_repeat_submit('article_save')           # ← 防重复
def article_save():
    ...
```

### 十四、数据库事务

> `transactional(f=None, *, max_retries: int = 3)`

将被装饰的视图函数包裹在 MongoDB 事务中执行。

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `max_retries` | `int` | `3` | 瞬态错误（如写入冲突）的最大重试次数 |

**支持两种用法：**

```python
# 无参（推荐，最常用）
@transactional

# 带参数
@transactional(max_retries=5)
```

**工作机制：**

1. 通过 `current_app.db_client.start_session()` 开启 MongoDB 会话
2. 调用 `session.start_transaction()` 启动事务
3. 在视图函数的 `kwargs` 中注入 `session` 参数
4. 视图函数成功 → `commit_transaction()`
5. 发生可重试错误（`WriteConflict`、`TransientTransactionError` 等）→ 自动重试
6. 如果 MongoDB 是**单节点部署（不支持事务）**，自动降级为非事务模式并记录警告，不影响业务

**配合 BLL 层使用：**

```python
# 视图层
@admin_router.route('/article/save', methods=['POST'])
@check_admin_login
@transactional
def article_save(**kwargs):
    session = kwargs.get('session')
    # 传给 BLL 层的事务方法
    ArticleBLL().save(data, session=session)
    LogBLL().add(log_data, session=session)
    # 全部 commit 或全部 rollback
```

> BLL 层需要使用 `add_trans` / `update_trans` 等事务方法（参考 `BllBase`），这些方法接收 `session` 参数。

### 十五、声明式参数校验

> `validate_params(schema: dict)`

声明式校验请求参数，校验通过后的数据存入 **`g.validated`**。

| 参数 | 类型 | 说明 |
|------|------|------|
| `schema` | `dict` | 校验规则字典（见下方） |

**支持的校验规则：**

| 规则 | 类型 | 用途 | 示例 |
|------|------|------|------|
| `required` | `bool` | 必填 | `True` |
| `type` | `type` | 期望类型 | `str`、`int`、`float`、`bool` |
| `min` | `int/float` | 最小值（数字）或最短长度（字符串） | `1` |
| `max` | `int/float` | 最大值（数字）或最大长度（字符串） | `150` |
| `min_length` | `int` | 字符串最小字符数 | `2` |
| `max_length` | `int` | 字符串最大字符数 | `50` |
| `pattern` | `str` | 正则匹配 | `r"^[a-zA-Z]"` |
| `choices` | `list` | 枚举值 | `[0, 1, 2]` |
| `email` | `bool` | 邮箱格式 | `True` |
| `mobile` | `bool` | 手机号格式 | `True` |

**校验失败时：**
- 返回 401 JSON，错误信息以 `；` 连接所有字段的错误
- 一个字段只报第一个错误

**示例：**

```python
@admin_router.route('/user/save', methods=['POST'])
@validate_params({
    "username": {"required": True, "type": str, "min_length": 2, "max_length": 50},
    "email":    {"required": True, "email": True},
    "age":      {"type": int, "min": 1, "max": 150},
    "mobile":   {"mobile": True},
    "status":   {"choices": [0, 1, 2]},
})
def user_save():
    # 所有校验通过的数据
    username = g.validated['username']
    email    = g.validated['email']
    age      = g.validated['age']      # 已自动转为 int
    status   = g.validated['status']   # 已自动转为 int
    ...
```

### 十六、响应缓存

> `cache_response(timeout: int)`

缓存视图函数的 JSON 响应结果。

| 参数 | 类型 | 说明 |
|------|------|------|
| `timeout` | `int` | 缓存有效时间（秒），如 `300` = 5 分钟 |

**缓存键生成规则：**

```
response_cache:{请求路径}:{查询字符串}:{用户语言}
```

**重要限制：**
- **仅缓存 `jsonify` 类型的响应**——不会缓存重定向、`render_template` 或错误页
- 适用于**读多写少、数据更新不频繁**的公开接口
- 如果视图函数返回非 JSON 响应，直接透传，不缓存

**示例：**

```python
@app.route('/api/article/list')
@cache_response(300)                     # 缓存 5 分钟
def article_list():
    articles = ArticleBLL().get_list()
    return jsonify(api_succesful(articles))


@app.route('/api/category/tree')
@cache_response(600)                     # 缓存 10 分钟
def category_tree():
    ...
```

## 装饰器编排顺序约定

多个装饰器叠加时，遵循 **"外层控制 → 内层业务"** 的顺序原则：

```python
# 推荐顺序（从上到下 = 从外到内）
@router.route(...)
@transactional                    # 7. 数据库事务（最外层，包裹整个请求）
@cache_response(300)              # 6. 响应缓存
@require_permission('xxx')        # 5. 权限检查
@check_admin_login                # 4. 登录验证
@check_img_code(10)               # 3. 人机验证
@no_repeat_submit('xxx')          # 2. 防重复提交
@validate_params({...})           # 1. 参数校验（最内层，最先执行）
def view_func(**kwargs):
    ...
```

实际执行顺序是**从下往上**：
`validate_params` → `no_repeat_submit` → `check_img_code` → `check_admin_login` → `require_permission` → ... → 视图函数
