# 主题与皮肤

# 一、主题的创建与启用

### 1、主题的创建

    主题文件保存在路径：website/themes

    每一个文件夹为一个主题。

    创建主题只要复制一份文件夹即可，然后修改文件夹的名称为你的主题名称。


### 2、主题的切换（启用）

    进入后台->系统设置->系统参数->主题与皮肤
    选择你刚复制出来的主题即可，但要想启用需要重启系统。

# 二、皮肤的创建与修改

网站皮肤文件，也就是模板文件位于：
> website/themes/你的主题/templates

### 1、首页皮肤的修改
    进入你复制好的主题目录，找到index.html文件即可在这个基础上修改你的首页前端代码了。

### 2、分类页面皮肤的制作
    分类皮肤文件默认为list.html，但你可为每个分类定制皮肤文件。

    - 创建分类模板
    进入后台->分类管理->分类模板，在这里可以创建你的分类模板
    创建分类模板有两种，一种是基于html文件的模板，可在主题目录下随意创建，并在后台创建分类模板的时候指定这个模板名称。
    另一种模板是直接存放在数据库中的，可以在后台直接编辑，适合简单的页面。

    - 绑定分类模板
    在创建分类的时候，可以在分类模板中选择刚刚创建好的模板。

### 3、内容页面皮肤的制作
    内容皮肤文件默认为content.html，但你可为每个内容定制皮肤文件。
    定制过程与分类皮肤一样

### 4、专题页面皮肤的制作
    专题皮肤文件默认为special.html，但你可为每个专题定制皮肤文件。
    定制过程与分类皮肤一样

### 5、其页面皮肤文件
以下皮肤文件不可修改文件名称，但你可以在这个文件上随意修改你的前端代码。

- login.html (登录页面)
- reg.html (注册页面)
- reg_info.html (注册协议页面)
- 404.html (404错误页面)
- err.html (常规错误页面)
- list_tag_value.html (标签内容列表页)
- user/index.html (用户控制面板主页)

# 三、内容页浏览量统计（计数信标）

### 1、它是怎么工作的

内容页渲染完成后，程序会**自动**在 `</body>` 之前插入一个 1×1 像素的透明图片，
称为“计数信标”：

```html
<img src="/hit/249536.gif" width="1" height="1" alt=""
     style="position:absolute;left:-9999px;top:0" aria-hidden="true">
```

访客打开页面时，浏览器会请求 `/hit/249536.gif`，服务端在这个请求里把该内容的
`hits` 字段加 1，并返回一个 43 字节的透明 GIF。

这样做的目的，是让**内容页本身保持“所有访客都完全一样”的纯静态响应**，从而可以
被 CDN / 反向代理完整缓存；同时浏览量又能照常统计。

### 2、主题作者需要做什么

**什么都不用做。**

信标由程序自动注入：无论内容页用的是主题目录下的 `content.html`，还是后台
“内容模板”里直接编辑的代码模板，都会自动带上。新建主题同样自动生效。

### 3、如果不想让程序自动注入

只要模板渲染出来的 HTML 里已经出现 `/hit/` 字符串，程序就认为你已经自行处理过，
不会再重复注入：

```html
<!-- 自己放的信标，程序不会再注入第二个 -->
<img src="/hit/{{ model.id }}.gif" width="1" height="1" alt="">
```

如果希望**彻底关闭**浏览量统计，把 `website/pages/cms_page.py` 中 `content()`
视图末尾的 `return _inject_hit_beacon(html, id)` 改成 `return html` 即可。

### 4、去重规则

同一个浏览器对同一篇内容，**5 分钟内只计一次**。实现方式是一个名为
`viewed_{内容id}` 的 cookie，它的作用域被限制在 `/hit/` 路径下，因此不会出现在
其他页面请求的 Cookie 头里。

### 5、编写内容页模板时的注意事项

因为内容页需要能被 CDN 缓存，请遵守以下三点：

- **不要在内容页里按访客身份渲染不同内容**（例如按登录状态输出不同 HTML）。
  否则 CDN 会把某一位访客看到的版本发给所有人。
- `content()` 视图已经**不再设置任何 cookie**。请不要在内容页的渲染流程里引入
  `set_cookie`，否则内容页会重新失去缓存能力。
- 需要显示随访客变化的信息（登录状态、购物车数量等）时，请在前端用异步请求获取，
  不要写进服务端渲染。

### 6、部署到 CDN 时的配置

- `/hit/` 路径**必须排除在 CDN 缓存之外**。该响应已经带有
  `Cache-Control: no-store`，但如果你在 CDN 上配置了“忽略源站缓存头、强制使用
  TTL”这类规则，计数就会失真（变成每个边缘节点每个 TTL 只计一次）。
- 内容页 `/a{id}.html` 的响应不再包含 `Set-Cookie`，可以放心交给 CDN 缓存。
