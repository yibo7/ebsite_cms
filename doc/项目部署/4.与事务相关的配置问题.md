# 四、与事务相关的配置问题

## 1. 哪些功能使用了事务

EbSite CMS 在以下两个场景中使用 MongoDB 多文档事务（ACID Transaction），确保数据一致性：

### 场景一：积分审核通过

- **文件**：`../../bll/apply_credites.py` → `apply_opt()` 方法
- **操作**：后台管理员审核通过用户积分申请时
- **事务内更新 3 个文档：**

| # | 集合 | 操作 | 说明 |
|---|------|------|------|
| ① | `apply_credites` | 更新 | 将审核申请单状态改为"已通过" |
| ② | `user` | 更新 | 增加对应用户的积分余额（带乐观锁） |
| ③ | `credit_logs` | 插入 | 记录一条积分变更流水 |

### 场景二：积分订单支付

- **文件**：`../../bll_orders/user_orders.py` → `complete_order()` 方法
- **操作**：用户购买积分，支付成功后处理订单
- **事务内更新 3 个文档：**

| # | 集合 | 操作 | 说明 |
|---|------|------|------|
| ① | `credit_orders` | 更新 | 将订单状态改为"已支付、已完成" |
| ② | `user` | 更新 | 增加对应用户的积分余额（带乐观锁） |
| ③ | `credit_logs` | 插入 | 记录一条积分变更流水 |

## 2. 为什么需要副本集

MongoDB 的多文档事务（`start_transaction()`）**必须运行在副本集环境中**，即使是单节点部署也需要以副本集模式启动。

> **原理**：MongoDB 事务依赖副本集的 oplog（操作日志）来实现回滚和持久化，单机模式（standalone）没有 oplog，因此不支持事务。

---

## 3. 部署时数据库配置操作

### 方式一：使用单节点副本集（推荐，资源占用与单机无异）

```bash
# 1. 启动 MongoDB 时指定副本集名称（以 cqsmg 为例）
mongod --replSet cqsmg --dbpath /data/db --port 27017

# 2. 连接 MongoDB
mongosh

# 3. 初始化副本集（只需执行一次）
rs.initiate()

# 4. 确认副本集状态
rs.status()
```

初始化成功后，MongoDB 就以单节点副本集模式运行，**日常使用与单机版完全一样**，读写性能无差异，也不增加额外资源消耗。

### 方式二：使用多节点副本集（生产环境高可用）

```bash
# 在每台服务器上启动 mongod
mongod --replSet cqsmg --dbpath /data/db --bind_ip 0.0.0.0

# 连接到其中一台，执行初始化
config = {
    _id: "cqsmg",
    members: [
        { _id: 0, host: "192.168.1.10:27017" },
        { _id: 1, host: "192.168.1.11:27017" },
        { _id: 2, host: "192.168.1.12:27017" }
    ]
}
rs.initiate(config)
```

### 方式三：Docker 部署

```yaml
# docker-compose.yml 示例
services:
  mongodb:
    image: mongo:7
    command: ["mongod", "--replSet", "cqsmg", "--bind_ip", "0.0.0.0"]
    ports:
      - "27017:27017"
    volumes:
      - mongo_data:/data/db
    # 初始化副本集（首次部署后需手动执行一次 rs.initiate()）

volumes:
  mongo_data:
```

## 4. 连接串配置

如果部署了副本集（包括单节点副本集），`../../conf/setting.json` 中的连接串应包含 `replicaSet` 参数：

```json
{
    "MONGODB_SERV": "mongodb://root:密码@服务器IP:27017/?replicaSet=cqsmg&authSource=admin"
}
```

> **注意**：请将 `密码` 和 `服务器IP` 替换为实际的值。

如果使用单节点副本集，连接串必须包含 `replicaSet=cqsmg`，否则驱动无法识别副本集，事务将无法正常工作。

## 5. 常见问题

### Q：单节点副本集和单机模式有什么区别？

| 对比项 | 单机模式 | 单节点副本集 |
|--------|---------|-------------|
| 启动参数 | `mongod` | `mongod --replSet cqsmg` |
| 初始化 | 无需 | 需执行一次 `rs.initiate()` |
| 事务支持 | ❌ 不支持 | ✅ 支持 |
| 资源占用 | 低 | 与单机几乎无差异（仅多一个 oplog 集合） |
| 日常运维 | 无差异 | 无差异 |

### Q：已经用单机模式跑了一段时间，能改成副本集吗？

可以。停掉 MongoDB，用 `--replSet` 参数重新启动，然后执行 `rs.initiate()` 即可，**已有数据不会丢失**。

### Q：如果不想用事务，怎么处理？

如果部署环境无法使用副本集，可以修改代码去掉事务，改用原子操作 + 最终一致性模式。但这样做代码会变得复杂，需要额外处理部分失败时的补偿逻辑，不建议优先选择。
