# MongoDB 事务配置

EbSite CMS 在部分涉及资金/积分的操作中使用 MongoDB 多文档事务（ACID Transaction），
确保数据一致性。**这些功能要求 MongoDB 以副本集模式运行**。

---

## 一、哪些功能使用了事务

### 场景一：积分审核通过

| 文件 | `bll/apply_credites.py` → `apply_opt()` 方法 |
|------|----------------------------------------------|
| 触发 | 后台管理员审核通过用户的积分申请 |
| 事务内操作 | |

| # | 集合 | 操作 | 说明 |
|---|------|------|------|
| ① | `apply_credites` | 更新 | 将申请单状态改为"已通过" |
| ② | `user` | 更新 | 增加用户积分余额（带乐观锁） |
| ③ | `credit_logs` | 插入 | 记录积分变更流水 |

### 场景二：积分订单支付

| 文件 | `bll_orders/user_orders.py` → `complete_order()` 方法 |
|------|------------------------------------------------------|
| 触发 | 用户购买积分，支付成功后处理订单 |
| 事务内操作 | |

| # | 集合 | 操作 | 说明 |
|---|------|------|------|
| ① | `credit_orders` | 更新 | 将订单状态改为"已支付" |
| ② | `user` | 更新 | 增加用户积分余额（带乐观锁） |
| ③ | `credit_logs` | 插入 | 记录积分变更流水 |

## 二、为什么需要副本集

MongoDB 的多文档事务（`start_transaction()`）**必须运行在副本集环境中**，
即使是单节点部署也需要以副本集模式启动。

> **原理**：事务依赖副本集的 oplog（操作日志）来实现回滚和持久化，
> 单机模式（standalone）没有 oplog，因此不支持事务。

---

## 三、部署配置方案

### 方案一：单节点副本集（推荐）

单节点副本集资源占用与单机版几乎无差异，只是多了一个 oplog 集合。
**日常使用与单机版完全一样，读写性能无差异。**

#### Linux / macOS

```bash
# 1. 启动 MongoDB 时指定副本集名称（以 cqsmg 为例）
mongod --replSet cqsmg --dbpath /data/db --port 27017

# 2. 连接 MongoDB
mongosh

# 3. 初始化副本集（只需执行一次）
rs.initiate()

# 4. 确认副本集状态
rs.status()
```

#### Windows

```cmd
# 1. 以副本集模式启动 MongoDB（假设数据目录为 C:\data\db）
mongod --replSet cqsmg --dbpath C:\data\db --port 27017

# 2. 另开一个命令行，连接 MongoDB
mongosh

# 3. 初始化副本集（只需执行一次）
rs.initiate()
```

> 如果 MongoDB 已注册为 Windows 服务，需要先停止服务，然后以命令行方式启动（仅首次），
> 初始化副本集后再重新注册服务。

#### Docker

```yaml
# docker-compose.yml 片段
services:
  mongodb:
    image: mongo:7
    command: ["mongod", "--replSet", "cqsmg", "--bind_ip", "0.0.0.0"]
    ports:
      - "27017:27017"
    volumes:
      - mongo_data:/data/db

volumes:
  mongo_data:
```

首次启动后需手动初始化副本集：

```bash
docker exec -it mongodb mongosh --eval "rs.initiate()"
```

### 方案二：多节点副本集（生产环境高可用）

```bash
# 每台服务器上启动 mongod
mongod --replSet cqsmg --dbpath /data/db --bind_ip 0.0.0.0

# 连接到其中一台，执行初始化
mongosh

config = {
    _id: "cqsmg",
    members: [
        { _id: 0, host: "192.168.1.10:27017" },
        { _id: 1, host: "192.168.1.11:27017" },
        { _id: 2, host: "192.168.1.12:27017" }
    ]
}
rs.initiate(config)
```

## 四、连接串配置

副本集模式下（包括单节点副本集），连接串必须包含 `replicaSet` 参数：

```json
{
    "MONGODB_SERV": "mongodb://用户名:密码@服务器IP:27017/?replicaSet=cqsmg&authSource=admin"
}
```

> **没有 `replicaSet` 参数**，驱动无法识别副本集，事务将无法正常工作。

### 各部署场景的连接串示例

| 场景 | 示例 |
|------|------|
| 本地无认证 | `mongodb://127.0.0.1:27017/?replicaSet=cqsmg` |
| 本地有认证 | `mongodb://root:密码@127.0.0.1:27017/?replicaSet=cqsmg&authSource=admin` |
| Docker 同网络 | `mongodb://mongodb:27017/?replicaSet=cqsmg` |
| 远程服务器 | `mongodb://root:密码@服务器IP:27017/?replicaSet=cqsmg&authSource=admin` |

## 五、常见问题

### Q：单节点副本集和单机模式有什么区别？

| 对比项 | 单机模式 | 单节点副本集 |
|--------|---------|-------------|
| 启动参数 | `mongod` | `mongod --replSet cqsmg` |
| 初始化 | 无需 | 需执行一次 `rs.initiate()` |
| 事务支持 | ❌ 不支持 | ✅ 支持 |
| 资源占用 | 低 | 与单机几乎无差异 |
| 日常运维 | — | 无差异 |

### Q：已经在用单机模式，能改成副本集吗？

可以。停止 MongoDB，用 `--replSet` 参数重新启动，然后执行 `rs.initiate()` 即可。
**已有数据不会丢失。**

### Q：不想用事务，怎么处理？

如果部署环境无法使用副本集，可以修改代码去掉事务，改用原子操作 + 最终一致性。
但代码会变得复杂，需要额外处理部分失败时的补偿逻辑，不建议优先选择。

### Q：连接串加了 replicaSet 后启动报错？

确认 MongoDB 已经以副本集模式启动（启动日志中有 `replSet` 相关输出），
并且已经执行过 `rs.initiate()`。可以在 `mongosh` 中执行 `rs.status()` 检查副本集状态。
