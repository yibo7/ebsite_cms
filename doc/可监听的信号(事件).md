# 可监听的信号（事件）

信号（Signal）是 Flask 框架提供的观察者模式实现，用于在系统关键操作点触发通知，
让模块和插件可以**松耦合地介入**系统流程，而无需直接 import 对方。

---

## 一、信号速查表

| 信号 | 触发时机 | 参数 | 返回值 | 状态 |
|------|----------|------|--------|------|
| `app_created` | APP 初始化结束后 | `app: Flask` | 无 | ✅ 已实现 |
| `class_saving` | 分类保存**前** | `model: NewsClassModel` | `(bool, str)` | ✅ 已实现 |
| `class_saved` | 分类保存成功后 | `model: NewsClassModel` | 无 | 🚧 未发送 |
| `content_saving` | 内容保存**前** | `model: NewsContentModel` | `(bool, str)` | ✅ 已实现 |
| `content_saved` | 内容保存成功后 | `model: NewsContentModel` | 无 | ✅ 已实现 |
| `user_reged` | 用户注册成功后 | `model: UserModel` | 无 | ✅ 已实现 |
| `user_reging` | 用户注册**前** | `model: UserModel` | `(bool, str)` | 🗓️ 规划中 |
| `user_loging` | 用户登录**前** | `model: UserModel` | `(bool, str)` | 🗓️ 规划中 |
| `user_loginged` | 用户登录成功后 | `model: UserModel` | 无 | 🗓️ 规划中 |
| `pay_saved_successful` | 支付成功回调后 | `model: PayBackInfo` | 无 | ✅ 已实现 |

> **图例**：✅ 已实现 = 已定义且已发送 / 🚧 未发送 = 已定义但尚未在代码中触发 / 🗓️ 规划中 = 尚未定义

## 二、各信号详解

### 2.1 app_created — APP 初始化结束

在应用创建完成、蓝图已注册、插件已加载后触发。适合在此给 `app` 添加全局扩展。

```
信号：     app_created
参数：     app: Flask
返回值：   无
```

监听示例：

```python
# 在模块的 __init__.py 或插件的 __init__ 中
from signals import app_created

@app_created.connect
def init_app(app):
    app.extensions['MyService'] = MyService(app)
```

---

### 2.2 class_saving — 分类保存前

在分类数据写入数据库**之前**触发。**返回 `(False, '原因')` 可以阻止保存。**

```
信号：     class_saving
参数：     model: NewsClassModel
返回值：   (bool, str)  — (是否继续, 阻止原因)
```

监听示例（模块中）：

```python
from signals import class_saving
from entity.news_class_model import NewsClassModel

def on_class_saving(model: NewsClassModel) -> (bool, str):
    if len(model.class_name) < 2:
        return False, '分类名称至少需要2个字符'
    return True, 'success'

class_saving.connect(on_class_saving)
```

监听示例（插件中）：

```python
@plugin_attribute("分类校验", "1.0", "ebsite")
class ClassNameValidator(PluginBase):
    def __init__(self, current_app):
        class_saving.connect(self.on_class_saving)
        super().__init__(current_app)

    def on_class_saving(self, model: NewsClassModel) -> (bool, str):
        return True, 'success'
```

> 🚧 此信号已定义但当前版本尚未在保存代码中触发，如需使用请自行在 `bll/new_class.py` 中添加发送逻辑。

### 2.4 content_saving — 内容保存前

在内容数据写入数据库**之前**触发。**返回 `(False, '原因')` 可以阻止保存。**

```
信号：     content_saving
参数：     model: NewsContentModel
返回值：   (bool, str)  — (是否继续, 阻止原因)
```

监听示例（参考商城模块中的 SKU 校验逻辑）：

```python
from signals import content_saving
from entity.news_content_model import NewsContentModel

def on_content_saving(model: NewsContentModel) -> (bool, str):
    # 自定义内容校验逻辑
    if model.title and len(model.title) < 5:
        return False, '标题至少需要5个字符'
    return True, 'success'

content_saving.connect(on_content_saving)
```

---

### 2.5 content_saved — 内容保存成功后

在内容成功写入数据库之后触发。

```
信号：     content_saved
参数：     model: NewsContentModel
返回值：   无
```

监听示例：

```python
from signals import content_saved
from entity.news_content_model import NewsContentModel

def on_content_saved(model: NewsContentModel):
    print(f"内容已保存: {model.title}")
    # 在此执行后续操作，如生成静态页、更新索引等

content_saved.connect(on_content_saved)
```

---

### 2.6 user_reged — 用户注册成功后

在用户注册成功（普通注册、手机注册、第三方登录注册）后触发。

```
信号：     user_reged
参数：     model: UserModel
返回值：   无
```

监听示例：

```python
from signals import user_reged
from entity.user_model import UserModel

def on_user_reged(model: UserModel):
    print(f"新用户注册: {model.username}")
    # 送积分、发送欢迎邮件等

user_reged.connect(on_user_reged)
```

---

### 2.7 pay_saved_successful — 支付成功后

在支付回调处理完成、订单支付确认后触发。

```
信号：     pay_saved_successful
参数：     model: PayBackInfo
返回值：   无
```

监听示例（参考商城订单处理）：

```python
from signals import pay_saved_successful
from entity.pay_back_model import PayBackInfo

def on_pay_success(model: PayBackInfo):
    print(f"订单 {model.order_no} 支付成功，更新订单状态")
    # 在此更新订单状态、发货等

pay_saved_successful.connect(on_pay_success)
```

## 三、如何监听信号

### 3.1 在模块中监听

在模块的 `__init__.py` 或单独的监听文件中：

```python
# eb_modules/my_module/__init__.py
from flask import Flask
from signals import content_saving, pay_saved_successful
from .. import module_attribute, ModuleInfo

@module_attribute('我的模块', '模块说明', '', None, 'author')
def module_init(app: Flask, model: ModuleInfo):
    content_saving.connect(on_content_saving)
    pay_saved_successful.connect(on_pay_success)

def on_content_saving(model) -> (bool, str):
    return True, 'success'

def on_pay_success(model):
    pass
```

### 3.2 在插件中监听

在插件的构造函数中连接信号：

```python
# plugins/my_plugin.py
from signals import content_saving
from plugins.plugin_base import PluginBase, plugin_attribute

@plugin_attribute("我的插件", "1.0", "ebsite")
class MyPlugin(PluginBase):
    def __init__(self, current_app):
        content_saving.connect(self.on_content_saving)
        super().__init__(current_app)

    def on_content_saving(self, model) -> (bool, str):
        return True, 'success'
```

### 3.3 三种监听方式对比

| 方式 | 适用场景 | 示例 |
|------|----------|------|
| `@信号.connect` 装饰器 | 模块/应用中的**独立函数** | `@content_saving.connect` |
| `信号.connect(函数)` | 模块中的具名函数 | `content_saving.connect(on_saving)` |
| `信号.connect(self.方法)` | **插件类**中的成员方法 | `content_saving.connect(self.on_saving)` |

## 四、信号的返回值机制

对于返回 `(bool, str)` 的信号：

| 返回值 | 含义 | 系统行为 |
|--------|------|----------|
| `(True, '任意信息')` | 校验通过 | 继续执行保存 |
| `(False, '错误原因')` | 校验不通过 | **阻止保存**，并向用户显示错误原因 |

多个监听者会依次执行，**任一监听者返回 `False` 都会阻止操作**。

---

## 五、注意事项

1. **监听函数执行顺序**：按照 `connect` 注册的顺序依次执行，不保证优先级
2. **性能影响**：监听函数应保持轻量，避免在信号中执行耗时操作
3. **不要 import 模块**：监听信号不需要 import 触发信号的模块，只需 import 信号本身
4. **信号定义位置**：所有信号统一在 `signals/__init__.py` 中定义
5. **返回值类型**：对于要求返回值的信号，请确保返回标准的 `(bool, str)` 类型，否则系统会抛出异常
