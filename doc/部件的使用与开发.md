# 部件的使用与开发

部件（Widget）是 EbSite CMS 中**可复用的页面区块**。你可以在后台创建一个部件实例，配置它的查询条件和模板，然后在任意页面上通过一行代码调用它。

---

## 一、快速开始

### 1.1 在页面中调用部件

```jinja
{{ widget('部件的MongoDB_ID')|safe }}
```

例如你在后台创建了一个"最新文章列表"部件，它的 `_id` 是 `64d2e7c93798563b080040c4`，在模板中这样写：

```jinja
<div class="sidebar">
    <h3>最新文章</h3>
    {{ widget('64d2e7c93798563b080040c4')|safe }}
</div>
```

### 1.2 部件运行流程

```
后台创建/编辑部件
    │
    ├─ 选择部件类型（如"内容查询部件"）
    ├─ 编写查询条件（MongoDB 语法）
    ├─ 编写数据绑定模板（Flask/Jinja2 模板）
    └─ 保存到 MongoDB（Widgets 表）
    
前台调用 get_widget_content(id)
    │
    ├─ 从 MongoDB 加载配置
    ├─ 根据 temp_type 找到对应的部件类
    ├─ 调用 temp_handler(model) 执行查询 + 渲染
    └─ 返回 HTML 字符串
```

## 二、部件类型一览

系统预置了一组通用部件，统一放在 `widgets/` 目录下，ID 命名格式为 `sys_N`：

| ID | 名称 | 类 | 说明 |
|----|------|---|------|
| `sys_1` | 分类查询部件 | `ClassWidget` | 按条件查询分类数据 |
| `sys_2` | 内容查询部件 | `ContentWidget` | 按条件查询内容数据 |
| `sys_3` | 专题查询部件 | `SpecialWidget` | 按条件查询专题数据 |
| `sys_4` | 用户查询部件 | `UserWidget` | 按条件查询用户数据 |
| `sys_5` | 文本框内容 | `TextBoxWidget` | 直接存储并显示纯文本 |
| `sys_6` | HTML 编辑框 | `HtmlBoxWidget` | 在线编辑 HTML 代码 |
| `sys_7` | 图集模板 | `PicBoxWidget` | 多图片上传+幻灯片渲染 |
| `sys_8` | 富文本编辑框 | `RichTextWidget` | WYSIWYG 富文本编辑器 |
| `sys_9` | 查询分类标签 | `TagByClassWidget` | 查询指定分类下的标签 |
| `sys_11` | 查询所有标签 | `TagByAllWidget` | 查询标签库所有标签 |
| `sys_12` | 随机查询内容 | `ContentWidgetRandom` | 随机获取内容数据 |

## 三、部件目录结构

重构后，每个部件是一个**自包含的文件夹**：

```
widgets/
├── widget_base.py                    ← 抽象基类（所有部件继承它）
├── __init__.py                       ← 触发自动发现
│
├── sys_1_class/                      ← 分类查询部件
│   ├── __init__.py                   ← Python 代码
│   └── admin.html                    ← 后台配置界面（只写特有字段）
│
├── sys_5_textbox/                    ← 文本框部件
│   ├── __init__.py
│   └── admin.html
│
├── sys_7_picbox/                     ← 图集部件
│   ├── __init__.py
│   └── admin.html
│
├── sys_8_richtext/                   ← 富文本部件
│   ├── __init__.py
│   └── admin.html
│
└── ... 其他部件
```

### 3.1 各文件的职责

| 文件 | 必须？ | 说明 |
|------|--------|------|
| `__init__.py` | **是** | 定义部件类，继承 `WidgetBase`，实现 `temp_handler()` |
| `admin.html` | 推荐 | 后台配置界面，只写部件**特有**的表单字段，通用部分（部件名称、缓存时间、保存按钮等）由基类自动包裹 |

### 3.2 admin.html 编写规则

`admin.html` **不需要**写以下内容（基类的 `_FORM_SKELETON` 会自动提供）：

- `{% extends 'base_admin.html' %}`
- `{% block content %}` / `{% endblock %}`
- `<form>` 标签
- **部件名称**输入框
- **缓存时间**输入框
- 隐藏字段 `_id`、`temp_type`
- **保存按钮**
- 错误提示

你只需要写部件**特有**的表单字段。例如 `sys_5_textbox/admin.html`：

```html
<div class="mb-3">
    <label>文本内容</label>
    <textarea name="temp_code" class="form-control" rows="10" cols="100" required>{{model.temp_code}}</textarea>
</div>
```

如果想自定义缓存提示文字，第一行加 `<!-- tip: -->` 注释：

```html
<!-- tip: 此部件查询较慢，建议开启缓存。 -->
<div class="mb-3">
    ...
</div>
```

## 四、开发一个新部件

开发一个新部件只需 3 步。

### 4.1 新建文件夹

```
widgets/my_module_1_news_list/
├── __init__.py
└── admin.html
```

文件夹名字建议用 `{模块名}_{序号}` 格式，确保 ID 全局唯一。

### 4.2 编写 __init__.py

```python
from markupsafe import Markup
from entity.widgets_model import WidgetsModel
from widgets.widget_base import WidgetBase


class NewsListWidget(WidgetBase):
    id = 'my_module_1'         # 字符串 ID，全局唯一
    name = '最新文章列表'       # 显示名称
    info = '按分类查询最新文章'  # 描述说明

    def temp_handler(self, model: WidgetsModel) -> Markup:
        """前台渲染：根据 model 配置查询数据，返回 HTML"""
        # 使用基类的通用查询方法
        return self._render_query(model)

    def bll_handler(self):
        """返回业务层对象，供 _render_query 使用"""
        from bll.new_content import NewsContent
        return NewsContent()
```

### 4.3 编写 admin.html

```html
<div class="mb-3">
    <label>数据绑定模板（Flask 模板语法）</label>
    <div style="width:100%;min-height:300px;" id="temp_code_div">{{model.temp_code}}</div>
    <textarea id="temp_code" style="display:none" name="temp_code" class="form-control" required>{{model.temp_code}}</textarea>
</div>

<div class="card mb-3">
    <div class="card-body">
        <h6 class="card-title mb-3" style="color:var(--bs-gray-700)">查询参数</h6>
        <div class="row g-3">
            <div class="col-md-8">
                <label class="form-label">MongoDB 查询条件</label>
                <textarea name="where_query" class="form-control font-monospace" rows="4">{{model.where_query}}</textarea>
            </div>
            <div class="col-md-4">
                <label class="form-label">排序字段</label>
                <input name="order_by" value="{{model.order_by}}" class="form-control font-monospace">
                <label class="form-label mt-2">排序方式</label>
                <select name="order_by_desc" class="form-control">
                    {{build_sel_item(desc_asc, 'value','name',model.order_by_desc)}}
                </select>
                <label class="form-label mt-2">查询记录数</label>
                <input type="number" name="limit" value="{{model.limit}}" class="form-control">
            </div>
        </div>
    </div>
</div>

<script>
$(function(){ init_ace("temp_code_div","temp_code"); });
</script>
```

### 4.4 自动发现机制

**无需手动注册。** 只要文件在项目任意位置的 `widgets/` 目录下，系统启动时会自动扫描发现：

```
项目根目录/
├── widgets/          ← 系统部件，自动发现
├── eb_modules/
│   └── eb_shop/
│       └── widgets/  ← 商城模块部件，自动发现
└── plugins/
    └── my_plugin/
        └── widgets/  ← 插件部件，自动发现
```

如果发现两个部件 ID 相同，启动时会立即报错并提示冲突。

## 五、WidgetBase 基类参考

### 5.1 子类必须定义的属性

| 属性 | 类型 | 说明 |
|------|------|------|
| `id` | `str` | 全局唯一标识，格式 `模块名_序号`（如 `sys_1`、`shop_1`） |
| `name` | `str` | 中文显示名称 |
| `info` | `str` | 描述说明 |

### 5.2 子类必须实现的方法

| 方法 | 返回值 | 说明 |
|------|--------|------|
| `temp_handler(model)` | `Markup` | 前台渲染入口，根据 `WidgetsModel` 配置返回 HTML |

### 5.3 子类可覆盖的钩子

| 方法 | 说明 |
|------|------|
| `bll_handler()` | 返回业务层对象，供 `_render_query()` 使用 |
| `saving(model)` | 保存前回调，可从 HTTP 请求中提取额外参数存入 `model.other` |

### 5.4 基类提供的通用方法

| 方法 | 说明 |
|------|------|
| `_render_query(model)` | 基于 MongoDB 条件查询的通用渲染（解析 `where_query`、`order_by`、`limit`） |
| `_parse_where_query(model)` | 安全解析 `where_query`（支持 JSON 和 Python 字典语法） |
| `get_admin_html()` | 读取同目录 `admin.html` 并包裹通用表单骨架 |

### 5.5 向后兼容

旧方法名（`temp_hanndler`、`bll_hanndler`、`where_hannder`）保留为别名，调用时会输出 `DeprecationWarning`。

## 六、数据模型（WidgetsModel）

字段存储在 MongoDB `Widgets` 表中：

| 字段 | 类型 | 说明 |
|------|------|------|
| `name` | `str` | 部件名称 |
| `temp_type` | `str` | 部件类型 ID（如 `sys_1`），兼容旧 int 格式 |
| `temp_code` | `str` | Jinja2 模板代码 |
| `where_query` | `str` | MongoDB 查询条件（JSON 格式） |
| `order_by` | `str` | 排序字段 |
| `order_by_desc` | `str` | `DESC` 或 `ASC` |
| `limit` | `int` | 最多返回条数 |
| `cache_time` | `int` | 渲染结果缓存秒数（0=不缓存） |
| `info` | `str` | 额外数据（如图集部件存图片路径列表） |
| `other` | `dict` | 扩展字段（如标签分类部件存 `class_ids`） |

## 七、从旧版迁移

### 7.1 数据库兼容

旧版 `temp_type` 字段存储 int（如 `1`、`2`），新版使用字符串（如 `sys_1`、`sys_2`）。
`resolve_widget_id()` 会自动将旧 int 映射到新字符串，**已有数据无需迁移**。

### 7.2 代码迁移

如果旧代码直接调用 `WidgetBase.__subclasses__()`，改为：

```python
# 旧
from widgets.widget_base import WidgetBase
subclasses = WidgetBase.__subclasses__()

# 新
from bll.widget_discover import get_all_widgets, get_widget
widgets = get_all_widgets()
widget = get_widget('sys_1')
```

## 八、常见问题

### 8.1 部件找不到或列表为空

1. 检查部件文件夹下是否有 `__init__.py`
2. 检查 `id` 属性是否已定义且不为空
3. 检查启动日志是否有 ID 冲突报错
4. 检查 `widgets/` 目录是否在项目根目录或已注册的扫描路径下

### 8.2 admin.html 不生效

1. 确认文件名为 `admin.html`（区分大小写）
2. 确认文件在部件文件夹根目录（与 `__init__.py` 同级）
3. 如果页面空白，检查 Jinja2 语法错误（如 `{{` 未闭合）

### 8.3 查询条件语法

部件查询条件支持三种格式，按优先级依次尝试：

```json
// 1. JSON（推荐）
{"status": 1, "class_n_id": {"$in": [1, 2, 3]}}

// 2. BSON 扩展格式（支持 ObjectId）
{"_id": {"$oid": "64d2e7c93798563b080040c4"}}

// 3. Python 字典（兼容旧数据）
{'status': 1, 'class_n_id': {'$in': [1, 2, 3]}}
```

### 8.4 如何将部件放在模块目录下？

```python
# eb_modules/eb_shop/__init__.py 中
from bll.widget_discover import add_scan_root
from pathlib import Path
add_scan_root(Path(__file__).parent)
```

然后在 `eb_modules/eb_shop/widgets/shop_1_product_list/__init__.py` 中定义部件即可。
