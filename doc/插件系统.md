# 插件系统

插件系统用于向系统注入可替换的服务实现。与模块（功能集合）不同，插件是**服务提供者**——
每个插件实现某个特定接口（如短信发送、文件上传、在线支付），系统可以通过插件管理器按需调用。

插件之间互不感知，通过统一接口实现"热插拔"式的服务替换。

---

## 一、插件管理器（PluginManager）

### 1.1 获取插件管理器

插件管理器在应用启动时自动初始化，挂载在 `current_app.pm` 上：

```python
from flask import current_app

pm = current_app.pm  # 获取插件管理器
```

### 1.2 管理器 API

| 方法 | 返回值 | 说明 |
|------|--------|------|
| `pm.plugins` | `list[PluginBase]` | 获取所有已加载的插件（按优先级排序） |
| `pm.get_by_id(plugin_id)` | `PluginBase \| None` | 根据插件 ID（即类名）查找插件实例 |
| `pm.get_by_type(type_class)` | `list[PluginBase]` | 获取指定类型的所有插件 |
| `pm.get_by_sms_plugins()` | `list[SMSSender]` | 获取所有短信发送插件 |
| `pm.get_by_email_plugins()` | `list[EmailSender]` | 获取所有邮件发送插件 |
| `pm.get_by_uploader_plugins()` | `list[Uploader]` | 获取所有文件上传插件 |
| `pm.get_by_payment_plugins()` | `list[PaymentBase]` | 获取所有在线支付插件 |
| `pm.send_sms(phone, message)` | `(bool, str)` | 调用**默认**短信插件发送短信 |
| `pm.send_email(to, title, body)` | `(bool, str)` | 调用**默认**邮件插件发送邮件 |
| `pm.upfile(file_bytes, model)` | `(bool, str)` | 调用**默认**上传插件上传文件 |

> **默认插件**：在系统配置中指定的插件 ID（如 `sms_sender_id`、`email_sender_id`、`uploader_id`）。

## 二、插件类型体系

系统预定义了 6 种插件接口，每个接口对应一个抽象基类：

```
PluginBase（所有插件的基类）
├── SMSSender         → 短信发送
├── EmailSender       → 邮件发送
├── Uploader          → 文件上传
├── OpenLoginBase     → 第三方登录
├── PaymentBase       → 在线支付
└── SearchBase        → 内容搜索
```

### 2.1 PluginBase（基类）

所有插件都继承自 `PluginBase`，它提供了：

| 方法/属性 | 说明 |
|-----------|------|
| `id` | 插件 ID，自动取类名（如 `TencentSMSSender`） |
| `name` | 插件名称（来自装饰器） |
| `version` | 版本号（来自装饰器） |
| `author` | 作者（来自装饰器） |
| `priority` | 排序优先级（来自装饰器） |
| `get_configs()` | 从数据库读取插件配置 |
| `set_configs(model)` | 保存插件配置到数据库 |
| `params_temp()` | 返回配置表单的 HTML 模板（可选重写） |
| `refush_config(config)` | 刷新插件配置到实例属性 |

### 2.2 SMSSender（短信发送）

```python
class SMSSender(PluginBase):
    def send_sms(self, phone_number: str, message: str) -> Tuple[bool, str]:
        """发送短信"""
        pass
```

### 2.3 EmailSender（邮件发送）

```python
class EmailSender(PluginBase):
    def send_email(self, to: str, title: str, body: str) -> Tuple[bool, str]:
        """发送邮件"""
        pass
```

### 2.4 Uploader（文件上传）

```python
class Uploader(PluginBase):
    def __init__(self, current_app):
        self.file_server: str = ""  # 文件访问域名
        super().__init__(current_app)
```

### 2.5 OpenLoginBase（第三方登录）

```python
class OpenLoginBase(PluginBase):
```

## 三、开发一个插件

### 3.1 文件位置

插件文件存放在项目根目录的 `plugins/` 下，每个插件一个 `.py` 文件：

```
plugins/
├── __init__.py              # 插件加载器（系统已有，勿改）
├── plugin_base.py           # 基类定义（系统已有，勿改）
├── plugin_manager.py        # 插件管理器（系统已有，勿改）
├── sms_sender_tencent.py    # 示例：腾讯云短信插件
├── email_sender_default.py  # 示例：默认邮件发送插件
├── uploader_local.py        # 示例：本地文件上传插件
├── uploader_tencentcos.py   # 示例：腾讯 COS 上传插件
├── open_login_weixin.py     # 示例：微信登录插件
└── payments/                # 支付类插件目录
    ├── payment_alipay.py
    └── payment_weixin.py
```

### 3.2 实现步骤

以腾讯云短信插件为例：

#### 第 1 步：导入基类和装饰器

```python
from typing import Tuple
from plugins.plugin_base import SMSSender, plugin_attribute
```

#### 第 2 步：添加装饰器

```python
@plugin_attribute("腾讯手机短信发送", "1.0", "ebsite")
```

`plugin_attribute` 参数说明：

| 参数 | 说明 |
|------|------|
| 第 1 个参数 | 插件名称（显示在后台列表中） |
| 第 2 个参数 | 版本号 |
| 第 3 个参数 | 作者标识 |
| `priority`（关键字） | 排序优先级，数字越小越靠前，默认 999 |

#### 第 3 步：实现插件类

```python
@plugin_attribute("腾讯手机短信发送", "1.0", "ebsite")
class TencentSMSSender(SMSSender):
    def __init__(self, current_app):
        # 在此定义配置参数（属性名==数据库字段名）
        self.app_id: str = ""           # 腾讯云 SDK AppID
        self.app_key: str = ""          # 腾讯云 App Key
        self.template_id: str = ""      # 短信模板 ID
        self.msg_sign_name: str = ""    # 短信签名
        super().__init__(current_app)   # 必须调用父类构造

    def send_sms(self, phone_number: str, message: str) -> Tuple[bool, str]:
        # 实现短信发送逻辑
        print(f'发送【{message}】到【{phone_number}】')
        return True, '发送成功'
```

#### 第 4 步：实现配置表单（可选）

如果需要后台配置界面，重写 `params_temp` 方法：

```python
def params_temp(self):
    return '''
    <div class="mb-3">
        <label>腾讯云 SDK AppID</label>
        <input name="app_id" value="{{model.app_id}}"
               class="form-control" required>
    </div>
    <div class="mb-3">
        <label>腾讯云 App Key</label>
        <input name="app_key" value="{{model.app_key}}"
               class="form-control" required>
    </div>
    <div class="mb-3">
        <label>短信模板 ID</label>
        <input name="template_id" value="{{model.template_id}}"
               class="form-control" required>
    </div>
    <div class="mb-3">
        <label>短信签名</label>
        <input name="msg_sign_name" value="{{model.msg_sign_name}}"
               class="form-control" required>
    </div>
    '''
```

> **注意**：`<input name="xxx">` 中的 `name` 属性值必须与构造函数中的属性名一致，
> 系统才能自动将配置保存到对应的属性上。

### 3.3 完整示例

```python
# plugins/my_sms_sender.py

from typing import Tuple
from plugins.plugin_base import SMSSender, plugin_attribute

@plugin_attribute("我的短信插件", "1.0", "ebsite", priority=500)
class MySmsSender(SMSSender):
    def __init__(self, current_app):
        self.api_key: str = ""
        self.api_secret: str = ""
        self.sign_name: str = "默认签名"
        super().__init__(current_app)

    def send_sms(self, phone_number: str, message: str) -> Tuple[bool, str]:
        # 在这里调用你的短信服务商 API
        print(f"发送短信: {message} -> {phone_number}")
        return True, "ok"

    def params_temp(self):
        return '''
        <div class="mb-3">
            <label>API Key</label>
            <input name="api_key" value="{{model.api_key}}" class="form-control" required>
        </div>
        <div class="mb-3">
            <label>API Secret</label>
            <input name="api_secret" value="{{model.api_secret}}" class="form-control" required>
        </div>
        <div class="mb-3">
            <label>短信签名</label>
            <input name="sign_name" value="{{model.sign_name}}" class="form-control">
        </div>
        '''
```

## 四、配置参数说明

### 4.1 配置的保存与加载

插件的配置通过 MongoDB 的 `PluginSettings` 集合持久化：

- **保存**：调用 `plugin.set_configs(dict)`，数据以插件 ID（类名）为 `_id` 存入数据库
- **加载**：构造时自动调用 `get_configs()`，将数据库中的值覆盖到实例的同名属性上
- **刷新**：调用 `plugin.refush_config(dict)` 可以手动刷新配置

### 4.2 配置参数的声明

配置参数需在构造函数 `__init__` 中声明为实例属性：

```python
def __init__(self, current_app):
    self.api_key: str = ""       # 默认值为空字符串
    self.timeout: int = 30       # 默认值为 30
    self.debug_mode: bool = False
    super().__init__(current_app)
```

这些属性名必须与 `params_temp()` 表单中的 `<input name="...">` 保持一致。

### 4.3 配置生效时机

配置修改保存后立即生效。`PluginBase` 的 `set_configs` 方法会自动调用 `refush_config` 将新配置刷新到实例属性，无需重启应用。

## 五、插件在代码中的使用

### 5.1 获取指定类型的全部插件

```python
pm = current_app.pm

# 获取所有短信插件
sms_plugins = pm.get_by_sms_plugins()
for plugin in sms_plugins:
    success, msg = plugin.send_sms("13800138000", "测试消息")
```

### 5.2 按 ID 获取指定插件

```python
pm = current_app.pm
plugin = pm.get_by_id("TencentSMSSender")  # 插件 ID = 类名
if plugin:
    plugin.send_sms("13800138000", "验证码：1234")
```

### 5.3 使用默认插件

系统通过后台配置指定各服务类型的默认插件（如 `sms_sender_id`、`email_sender_id`），
可以通过管理器快捷方法调用：

```python
# 发送短信（使用系统配置的默认短信插件）
success, msg = current_app.pm.send_sms("13800138000", "您的验证码是：1234")

# 发送邮件（使用系统配置的默认邮件插件）
success, msg = current_app.pm.send_email("user@example.com", "标题", "邮件内容")

# 上传文件（使用系统配置的默认上传插件）
success, path = current_app.pm.upfile(file_bytes, file_model)
```

## 六、开发规范与最佳实践

### 6.1 命名规范

- **文件名**：使用小写字母和下划线，如 `sms_sender_aliyun.py`
- **类名**：使用大驼峰命名，如 `AliyunSMSSender`
- **插件 ID**：即类名，系统自动使用，因此需保证全局唯一

### 6.2 配置参数

- 所有配置属性在 `__init__` 中声明并赋予默认值
- `params_temp()` 返回有效的 Jinja2 HTML 模板
- **必须**调用 `super().__init__(current_app)`，否则配置无法加载

### 6.3 返回值规范

所有插件的公开方法应返回统一的 `Tuple[bool, str]`：

- `(True, '成功信息')` — 操作成功
- `(False, '错误描述')` — 操作失败，第二项为错误原因

### 6.4 注意事项

- 插件文件放在 `plugins/` 目录下即可被自动发现，**无需额外注册**
- 如果插件需要监听系统信号，在 `__init__` 中连接
- 插件不能 import 其他插件，应通过 `pm.get_by_id()` 调用
- 多个同类型插件可共存，系统通过后台配置指定默认使用的那个

## 七、常见问题

### Q：插件没有在后台列表中显示？

检查：
1. 文件是否以 `.py` 结尾，放在 `plugins/` 目录下
2. 类上是否有 `@plugin_attribute` 装饰器
3. 类是否继承了正确的抽象基类（`SMSSender`、`EmailSender` 等）
4. `__init__` 中是否调用了 `super().__init__(current_app)`

### Q：如何替换默认的短信/邮件/上传插件？

在系统后台 → 插件管理页面中，将对应服务类型的默认插件 ID 改为新插件的类名即可。

### Q：插件配置保存后为什么没有生效？

插件配置通过 `set_configs` 保存后会自动调用 `refush_config` 刷新到实例属性。
如果未生效，检查表单 `<input name="xxx">` 中的 `name` 是否与构造函数中的属性名一致。
