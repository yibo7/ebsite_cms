# 三种上传插件的使用

## 统一文件访问接口

所有上传插件上传的文件，统一通过以下接口访问：

```
GET /api/file/<file_id>.<ext>
```

示例：

```
/api/file/66c955480912afeaefb48a9d.png
```

**URL 必须带后缀名**，不带后缀的请求返回 404。后缀用于 CDN 缓存识别，实际文件类型由数据库的 `mimetype` 字段决定。

无论使用哪个上传后端（MongoDB、本地磁盘、腾讯COS），前端都使用同一格式的 URL，
上传接口返回的 `data.url` 已经是此格式。

### 工作原理

```
GET /api/file/66c95...9d.png
  ↓ 正则提取 file_id
查 FileModel 表 → 找到 plugin_id
  ↓ 按 plugin_id 找到对应的上传插件实例
调插件.read(model)
  ├─ MongoDB 插件  → 从 model.content 取 bytes  → 代理输出
  ├─ 本地存储插件  → 从 model.url 反推磁盘路径  → 代理输出
  └─ COS 插件      → 302 重定向到 COS 直读 URL
```

### 文件命名规则

文件在存储层使用 **MD5 哈希值** 作为文件名：

| 插件 | 磁盘/COS 路径 |
|---|---|
| 本地 | `uploads/{subdir}/{md5}.{ext}` |
| COS | `upfile/{subdir}/{md5}{ext}` |
| MongoDB | 无独立文件，内容存 `model.content` |

> 相同内容的文件（相同 MD5）在磁盘或 COS 上天然只存一份，避免重复占用空间。
> DB 层的 MD5 去重防止重复记录，存储层的 MD5 命名防止重复文件。

### 文件保存子目录配置

在 `conf/setting.json` 中设置 `FileStorageSubdir`，可让支持文件系统分层（本地磁盘、COS 等）的插件将文件保存到子目录中：

```json
{
    "FileStorageSubdir": "site_a"
}
```

当此值为空字符串 `""` 时，文件直接保存在根目录下。

当设置了子目录（如 `site_a`）时：

| 插件 | 存储路径 | 浏览器访问 URL |
|---|---|---|
| 本地 | `uploads/site_a/{md5}.png` | `/api/file/{_id}.png` ← **扁平** |
| COS | `upfile/site_a/{md5}{ext}` | `https://cdn.example.com/upfile/site_a/{md5}{ext}` |
| MongoDB | 忽略此配置 | `/api/file/{_id}.png` |

> **URL 始终为扁平格式** `/api/file/{id}.ext`，不暴露子目录路径和 MD5。
> 子目录仅用于磁盘/COS 存储层的文件组织，对前端完全透明。

### 上传记录

每次上传记录上传者的账号和 ID，存储在 `FileModel.user_name` 和 `FileModel.user_id` 字段中。

### 管理后台

文件管理列表的操作列包含：
- **访问** — 新标签页打开 `{id}.{ext}`，直接查看/下载文件
- **删除** — 删除文件记录

### 批量导入数据的图片处理

批量导入数据时（如从 JSON 导入产品信息），如果图片已经是按目录整理好的本地文件，可以直接放入 `static/` 目录：

```
website/themes/eb_shop/static/products/GX-IR1730-001/1.jpg
website/themes/eb_shop/static/products/GX-IR1730-001/2.jpg
```

导入时在 NewsContent 中直接存储 `/products/GX-IR1730-001/1.jpg` 即可，Flask 会作为静态文件直接输出。这样做的好处是文件按产品编码组织，一目了然，不需要走插件上传流程。

> 两种图片路径在 CMS 中可共存：
> - 批量导入的：`/products/{code}/{filename}` → static 静态文件
> - 后台新上传的：`/api/file/{id}.ext` → 上传插件系统
>
> 都是浏览器可访问的 URL，混用在同一字段中不受影响。

## 一、MongoDB 上传插件

适合小量文件存储，文件内容直接保存在 MongoDB 数据库的 `model.content` 字段中。
默认使用此插件。

访问地址：

> /api/file/\<file_id\>.\<ext\>

后端读取方式：从 `FileModel.content` 字段直接返回 bytes。

> MongoDB 插件无视 `FileStorageSubdir` 配置，`model.url` 始终为空字符串。

---

## 二、本地文件上传

将文件上传到项目 `website/uploads/` 目录下。可配合 `FileStorageSubdir` 配置使用子目录。

访问地址：

> /api/file/\<file_id\>.\<ext\>

磁盘存储路径：

```
# 无子目录时
website/uploads/{md5}.png

# 设置 FileStorageSubdir = "site_a" 时
website/uploads/site_a/{md5}.png
```

`model.url` 记录真实存储路径（如 `/uploads/site_a/{md5}.png`），后台管理可直接看出文件位置。
后端读取方式：用 `model.url` 直接拼接磁盘路径。

---

## 三、腾讯 COS 存储上传

依赖 `cos-python-sdk-v5`，使用前请安装：

```bash
pip install -U cos-python-sdk-v5
```

访问地址为 COS 对象存储的直读 URL（不经过 CMS 服务器），由插件配置中的 `file_server` 和 `bucket` 决定：

> https://\<自定义域名\>/\<路径\>/\<md5\>.\<ext\>

COS 上的存储路径：

```
# 无子目录时
upfile/{md5}.png

# 设置 FileStorageSubdir = "site_a" 时
upfile/site_a/{md5}.png
```

后端读取方式：返回 `redirect:` 标记，CMS 收到后执行 302 重定向到 COS 直读 URL，
浏览器直接访问 COS，不占用 CMS 服务器带宽。

## 四、插件 `read()` 接口说明

每个上传插件可选择性实现 `read()` 方法，用于统一读接口获取文件内容：

```python
def read(self, model: FileModel) -> Tuple[bool, Union[bytes, str, None]]:
    """
    :param model: 文件模型（包含 _id、url、mimetype 等字段）
    :return:
        (True, bytes)           → CMS 代理输出文件内容
        (True, 'redirect:<url>')→ CMS 302 重定向到该 URL
        (False, 错误信息)        → 文件不存在
    """
```

新增上传插件时，只需实现 `upload()` 和 `read()` 两个方法，
无需在 API 层注册新路由。
