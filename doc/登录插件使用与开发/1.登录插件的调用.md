# 登录插件的调用

第三方登录插件允许用户使用微信、Google、GitHub 等外部账号快速登录系统，无需注册新账号。

---

## 一、整体流程

```
用户点击"微信登录"
       │
       ▼
前端 JS 调用 API 获取授权 URL
       │
       ▼
浏览器跳转到第三方授权页（微信扫码 / Google 选号）
       │
       ▼
用户完成授权
       │
       ▼
第三方重定向到系统回调地址
       │
       ▼
回调路由处理：
  1. 调插件 call_back() 获取用户信息
  2. 按 openid 查找或自动注册用户
  3. 生成登录 token、设置 cookie
  4. 重定向到首页（已登录状态）
```

---

## 二、前端调用

### 2.1 在登录页添加按钮

在任意登录模板中，通过 `onclick` 调用全局 JavaScript 函数 `openlogin()`，参数为**插件 ID**（即类名）：

```html
<a onclick="openlogin('OpenLoginWixin')">微信登录</a>
<a onclick="openlogin('OpenLoginGoogle')">Google 登录</a>
```

### 2.2 openlogin() 函数

该函数定义在每个主题的 `comm.js` 中：

```javascript
function openlogin(plugin_id){
    get_json('/api/app/openlogin?pid='+plugin_id, (rz)=>{
        // rz.code === 0 时， rz.data 为第三方授权页 URL
        window.location.href = rz.data;
    });
}
```

流程说明：

| 步骤 | 说明 |
|------|------|
| 1 | 调用 `/api/app/openlogin?pid=OpenLoginGoogle` |
| 2 | 后端返回第三方 OAuth 授权页 URL |
| 3 | 前端将浏览器重定向到该 URL |
| 4 | 用户在第三方页面完成授权 |
| 5 | 第三方重定向回系统回调地址，完成登录 |

---

## 三、后端 API

### 3.1 获取授权 URL

```
GET /api/app/openlogin?pid=<插件ID>
```

**参数**：

| 参数 | 必填 | 说明 |
|------|------|------|
| `pid` | 是 | 插件 ID（即插件类名，如 `OpenLoginGoogle`、`OpenLoginWixin`） |

**返回**：

```json
// 成功
{"code": 0, "data": "https://accounts.google.com/o/oauth2/v2/auth?...", "msg": ""}

// 失败
{"code": -1, "msg": "错误描述"}
```

### 3.2 回调地址（由第三方平台调用）

```
GET /api/app/open_login_back?plugin=<插件ID>&code=<授权码>&state=<防伪串>
```

此路由**由第三方平台在用户授权后自动重定向调用**，无需前端主动请求。

处理逻辑：

1. 校验 `state` 防止 CSRF 攻击
2. 调用对应插件的 `call_back()`，用 `code` 换取 access_token 并获取用户信息
3. 按 `openid` 查找本地用户：
   - **已存在** → 更新头像 / 昵称 / 邮箱
   - **不存在** → 自动注册新用户（随机生成密码）
4. 生成登录 token 并设置 Cookie
5. 浏览器重定向到首页 `/`（已登录状态）

## 四、用户数据

### 4.1 自动注册规则

第三方登录成功后，系统会自动创建本地用户账号：

| 字段 | 来源 |
|------|------|
| `username` | 第三方 `openid`（或手机号，如果有） |
| `ni_name` | 第三方昵称 |
| `avatar` | 第三方头像 URL |
| `email_address` | 第三方邮箱（Google/Apple 等提供） |
| `password` | 随机 8 位密码（用户无法用密码登录，只能走第三方登录） |
| `openid` | 第三方平台唯一 ID，用于后续登录识别 |
| `group_id` | 系统配置的默认注册用户组 |

### 4.2 判断用户来源

用户的 `UserModel.openid` 字段记录了绑定的第三方平台 ID。
通过 `openid` 前缀可判断来源：

| openid 特征 | 来源 |
|-------------|------|
| 以数字开头（微信 OpenID） | 微信登录 |
| `google-xxx` 格式 | Google 登录（Google 返回的 `sub` 或 `id` 以数字为主，但建议自行标注） |

> 可在 `UserModel` 上扩展 `login_provider` 字段来明确标识来源平台，当前版本通过 `openid` 字段存储。

## 五、管理后台

### 5.1 插件配置

在系统后台 → **插件管理** → **三方登录** 中：

1. 查看已安装的所有第三方登录插件
2. 点击插件进入配置页，填写对应平台的 AppId / AppSecret / ClientId 等凭据
3. 配置保存后**立即生效**，无需重启应用

### 5.2 查看用户

后台用户管理中可以看到通过第三方登录注册的用户，其 `openid` 字段不为空。

## 六、常见问题

### Q：回调后页面跳转到首页但未登录？

可能原因：

1. **插件配置错误** — 检查后台插件配置中的 ClientId / Secret 是否正确
2. **回调地址不匹配** — 检查第三方平台后台配置的回调 URI 是否与插件页显示的完全一致
3. **CSRF state 校验失败** — 页面加载后超过 5 分钟才完成授权（state 过期）
4. **域名不一致** — 开发环境使用 `127.0.0.1`，但第三方平台配置了 `localhost`

### Q：用户已有本地账号，如何与第三方账号绑定？

当前版本采用"首次登录自动注册、再次登录自动识别"的策略，同一第三方账号永远对应同一本地用户。如果需要"将第三方账号绑定到已有本地账号"，需在回调路由中扩展绑定逻辑。

### Q：一个用户能否绑定多个第三方账号？

当前 `UserModel.openid` 为单字段，一个用户只能关联一个第三方账号。如需多账号绑定，需扩展 `UserModel` 增加 `openid_google`、`openid_wechat` 等多字段。

### Q：用户密码是多少？

通过第三方登录自动注册的用户，系统随机生成了 8 位密码。用户无法用账号+密码方式登录，只能通过对应的第三方平台登录。如果用户需要设置密码，可在个人中心添加密码。
