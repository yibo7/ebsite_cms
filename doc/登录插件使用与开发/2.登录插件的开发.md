# 登录插件的开发

本文档指导如何开发一个新的第三方登录插件（如接入 GitHub、Apple、QQ 等 OAuth 登录）。

---

## 一、接口说明

### 1.1 OpenLoginBase（抽象基类）

所有第三方登录插件必须继承 `OpenLoginBase`，并实现两个抽象方法：

```python
class OpenLoginBase(PluginBase):
    @abstractmethod
    def login(self) -> Tuple[bool, str]:
        """
        OAuth 第一步：发起登录。

        构造第三方平台的 OAuth 授权 URL，
        成功时返回 (True, 授权页 URL)，前端将用户浏览器重定向到该 URL。
        失败时返回 (False, 错误信息)。
        """
        pass

    @abstractmethod
    def call_back(self, request: Request) -> Tuple[bool, str, UserCallBackModel]:
        """
        OAuth 第二步：处理回调。

        接收第三方平台的授权回调请求，完成：
          1. 校验 state 防止 CSRF
          2. 用 code 换取 access_token
          3. 用 access_token 获取用户信息
        返回标准化的 UserCallBackModel。
        """
        pass
```

### 1.2 基类提供的辅助方法

子类可以直接调用的通用能力：

| 方法 | 说明 |
|------|------|
| `_generate_state(expire_seconds=300)` | 生成防 CSRF 的 state 参数并缓存，返回 state 字符串 |
| `_verify_state(state)` | 校验回调传入的 state 是否合法有效，返回 `bool` |
| `get_call_back_url()` | 获取当前插件的回调地址（子类可覆写以适配特殊平台要求） |

### 1.3 UserCallBackModel（用户信息模型）

`call_back()` 方法必须返回此对象，系统根据此模型自动注册或更新用户：

```python
class UserCallBackModel:
    user_open_id: str       # [必填] 第三方平台用户唯一 ID
    email: str              # [可选] 邮箱（Google/Apple 必返，微信不返）
    email_verified: bool    # [可选] 邮箱是否已验证
    user_ni_name: str       # [可选] 用户昵称
    avatar_url: str         # [可选] 用户头像 URL
    token: str              # [可选] 第三方 access_token

    # 以下为平台特有可选字段（如微信的性别/地区），多数平台不返回
    sex: str
    city: str
    country: str
    province: str
```

> **说明**：`email` 和 `email_verified` 是 Google/Apple 等平台的核心返回值，
> 如果第三方平台不提供邮箱（如微信），保持默认空值即可。

## 二、开发步骤

### 第 1 步：创建插件文件

在 `plugins/` 目录下新建 `.py` 文件，命名采用小写字母加下划线：

```
plugins/open_login_github.py    # GitHub 登录插件
plugins/open_login_qq.py        # QQ 登录插件
plugins/open_login_apple.py     # Apple 登录插件
```

### 第 2 步：导入基类和装饰器

```python
from typing import Tuple
import requests
from flask import Request
from entity.user_call_back_model import UserCallBackModel
from plugins.plugin_base import OpenLoginBase, plugin_attribute
```

### 第 3 步：添加装饰器

```python
@plugin_attribute("GitHub 登录", "1.0", "ebsite")
```

`plugin_attribute` 参数：

| 参数 | 说明 |
|------|------|
| 第 1 个参数 | 插件名称（显示在后台列表中） |
| 第 2 个参数 | 版本号 |
| 第 3 个参数 | 作者标识 |
| `priority`（关键字） | 排序优先级，数字越小越靠前，默认 999 |

### 第 4 步：实现插件类

```python
@plugin_attribute("GitHub 登录", "1.0", "ebsite")
class OpenLoginGithub(OpenLoginBase):
    def __init__(self, current_app):
        self.info = "基于 GitHub OAuth 的登录插件"
        self.client_id: str = ""
        self.client_secret: str = ""
        super().__init__(current_app)

    def login(self) -> Tuple[bool, str]:
        """构造 GitHub OAuth 授权 URL"""
        state = self._generate_state()  # ← 基类提供
        url = (
            "https://github.com/login/oauth/authorize"
            f"?client_id={self.client_id}"
            f"&redirect_uri={self.get_call_back_url()}"
            f"&state={state}"
            f"&scope=read:user%20user:email"
        )
        return True, url

    def call_back(self, request: Request) -> Tuple[bool, str, UserCallBackModel]:
        """处理 GitHub OAuth 回调"""
        code = request.args.get('code')
        state = request.args.get('state')
        error = request.args.get('error')
        user_info = UserCallBackModel()

        # 用户拒绝授权
        if error:
            return False, f'用户拒绝了授权', user_info

        # 校验 state（← 基类提供）
        if not self._verify_state(state):
            return False, 'state 校验失败', user_info

        if not code:
            return False, '缺少 code 参数', user_info

        # 用 code 换取 access_token
        token_resp = requests.post(
            "https://github.com/login/oauth/access_token",
            headers={'Accept': 'application/json'},
            data={
                'client_id': self.client_id,
                'client_secret': self.client_secret,
                'code': code,
                'redirect_uri': self.get_call_back_url(),
            },
        )
        if token_resp.status_code != 200:
            return False, '获取 access_token 失败', user_info
        access_token = token_resp.json().get('access_token', '')
        if not access_token:
            return False, '返回数据中没有 access_token', user_info

        # 拉取用户信息
        headers = {'Authorization': f'Bearer {access_token}'}
        user_resp = requests.get('https://api.github.com/user', headers=headers)
        if user_resp.status_code != 200:
            return False, '获取用户信息失败', user_info
        gh_user = user_resp.json()

        # 拉取用户邮箱（GitHub 的 email 字段可能为 null，需要单独请求邮箱 API）
        email_resp = requests.get('https://api.github.com/user/emails', headers=headers)
        primary_email = ''
        if email_resp.status_code == 200:
            emails = email_resp.json()
            for em in emails:
                if em.get('primary'):
                    primary_email = em.get('email', '')
                    break

        # 填充标准化的用户信息
        user_info.user_open_id = f"github_{gh_user.get('id', '')}"
        user_info.email = primary_email
        user_info.email_verified = True
        user_info.user_ni_name = gh_user.get('name') or gh_user.get('login', '')
        user_info.avatar_url = gh_user.get('avatar_url', '')
        user_info.token = access_token

        return True, '', user_info
```

## 三、插件注册

插件文件放在 `plugins/` 目录下即可被**自动发现**，无需手动注册。

自动发现机制（`plugins/__init__.py` 中的 `load_plugins` 函数）：

1. 遍历 `plugins/` 目录下所有 `.py` 文件
2. 动态 import 每个模块
3. 查找带有 `@plugin_attribute` 装饰器的类
4. 实例化并加入插件列表

但为了代码可读性和 IDE 支持，建议在 `plugins/__init__.py` 顶部添加显式 import：

```python
from plugins.open_login_github import OpenLoginGithub
```

## 五、最佳实践

### 5.1 state 防 CSRF

**必须**在 `login()` 中调用 `_generate_state()` 生成 state，附加到授权 URL；
在 `call_back()` 中最先调用 `_verify_state()` 校验。这是防止 OAuth 回调被伪造的关键安全措施。

```python
# login() 中
state = self._generate_state()
url = f"...&state={state}"

# call_back() 中最先校验
if not self._verify_state(request.args.get('state')):
    return False, 'state 校验失败', UserCallBackModel()
```

### 5.2 user_open_id 的稳定性

`user_open_id` 是关联本地用户的关键字段，**必须选择第三方平台永不改变的唯一标识**：

- Google → `google_user['id']`（或 OpenID Connect 的 `sub` 声明）
- GitHub → `gh_user['id']`（纯数字）
- 微信 → `wx_user['openid']`

建议为 `user_open_id` 添加平台前缀（如 `github_12345`），避免不同平台 ID 冲突。

### 5.3 回调地址

- `get_call_back_url()` 默认返回 `/api/app/open_login_back?plugin=你的类名`
- 如果第三方平台**要求完整的 HTTPS 回调 URL**（如 Apple），子类可覆写此方法：

```python
def get_call_back_url(self) -> str:
    return quote(f'https://yourdomain.com/api/app/open_login_back?plugin={self.id}')
```

### 5.4 email 的获取

不同平台获取邮箱的方式不同：

| 平台 | 获取方式 |
|------|----------|
| Google | `/oauth2/v2/userinfo` 直接返回 `email` 和 `verified_email` |
| 微信 | **不返回邮箱**，保持 `email` 为空即可 |
| GitHub | 需单独请求 `GET /user/emails`，找 `primary=true` 的条目 |
| Apple | ID Token（JWT）中解析 `email` 和 `email_verified` 声明 |

### 5.5 用户拒绝授权的处理

部分平台在用户拒绝授权时会带 `error` 参数回调（如 Google 返回 `error=access_denied`），应在 `call_back()` 中优先处理：

```python
error = request.args.get('error')
if error:
    return False, f'用户拒绝了授权', UserCallBackModel()
```

### 5.6 使用标准的 requests 库

所有现有插件均使用 `requests` 库进行 HTTP 请求，保持一致即可。特殊平台可能需要额外参数（如 Apple 需要 `client_secret` 是 JWT 格式），在插件内部处理即可。

## 六、常见问题

### Q：插件创建后后台没有显示？

检查：
1. 文件是否以 `.py` 结尾，放在 `plugins/` 目录
2. 类上是否有 `@plugin_attribute` 装饰器
3. 类是否继承了 `OpenLoginBase`
4. `__init__` 中是否调用了 `super().__init__(current_app)`

### Q：如何调试 OAuth 流程？

1. 在第三方平台后台将回调地址设为 `http://127.0.0.1:5000/api/app/open_login_back?plugin=xxx`
2. 本地启动系统，点击前端登录按钮
3. 观察浏览器地址栏跳转
4. 如果回调失败，浏览器会被重定向到 `/?login_error=xxx`，查看 URL 中的错误信息

### Q：access_token 过期了怎么办？

`OpenLoginBase` 预留了可选的 `refresh_token()` 和 `revoke()` 接口（当前非抽象方法，子类按需实现）。如果平台支持 refresh_token，可在 `call_back()` 中将 `refresh_token` 存入 `UserCallBackModel.token` 或 `extra_data` 中，后续在业务代码中调用刷新。

### Q：用户信息中的字段不够用怎么办？

`UserCallBackModel` 中的 `token` 字段存储了第三方平台的 `access_token`，可在业务代码中用此 token 主动调用第三方 API 获取更多信息。
