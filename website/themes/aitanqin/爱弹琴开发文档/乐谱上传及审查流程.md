目前乐谱来源主要分为用户主动上传与采集自动上传两各路

# 一、用户主动上传


### 1.上传接口及对应上传的类型

主动上传目前主要有两种上传接口，一种是上传gpt与xml的，一种是上传图片的

> 调用接口：EbSite.Web.Ex.Controllers.UpTabGtpXml(int ut, string token, int? dataid = 0)
> 上传类型：ui对应1GTP,2XML

> 调用接口：EbSite.Web.Ex.Controllers.UpTabImg(int ut, string token)
> 上传类型：图片

### 2.gtp、xml与图片上传成功后临时目录如下：
无论哪种上传乐谱上传都会先放在临时目录，经
- scores/gpt/temp/
- scores/xml/temp/
- scores/image/temp/

### 3.上传后处理
上传后处理在Atq.Service项目中，目前主要处理gpt与xml两种上传，图片乐谱的上传在当时上传就已经处理完成
上传后处理主要是将临时文件移到正式目录，并生成gpt与xml的图片，后上传gpt与xml的图片到云端

- #### GTP乐谱上传后处理	
	在Atq.Service中通过GtpToImg处理	
	- 调用表eb_newscontent，条件为 Annex21=1的记录
	- 调用类库生成图片
	- 将临时GTP文件移到正式目录
	- 将生成的图片文件上传到COS或云盘
	- 上传GTP文件到COS或云盘(目前没有使用，只使用了本地的gpt文件)

- #### XML乐谱上传后处理
	在Atq.Service中通过XmlToImg处理
	
	- 调用表eb_nc_xml_piano，条件为 Annex21=1的记录
	- 调用类库生成图片
	- 将临时GTP文件移到正式目录
	- 将生成的图片文件上传到COS或云盘
	- 上传GTP文件到COS或云盘(目前没有使用，只使用了本地的xml文件)

- #### 图片乐谱上传后处理
	图片乐谱上传后处理在前端上时已经完成，主要是分为管理员上传用户上传，管理员上传当时将图片上传到正式目录，用户上传会在审核成功后将图片移动到正式目录。


# 二、采集自动上传 
采集的乐谱一般在XS.ModuleForCore中完成，目前提供图片类与XML的上传。
- 图片类乐谱，在客户端直接处理图片，并生成缩回图，上传到云盘，接着直接发布内容。
- XML 的更新会上传xml文件到atq,然后由【上传后处理】程序处理。
